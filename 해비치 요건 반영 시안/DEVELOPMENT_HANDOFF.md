# 해비치 급식 App 퍼블리싱 개발 전달 가이드

## 1. 전달 범위

이 폴더는 임직원용 해비치 급식 App의 HTML 퍼블리싱 결과물이다. 화면 구조, 컴포넌트 스타일, 페이지 이동 흐름과 검토용 클라이언트 인터랙션을 포함한다.

- 기준 문서: `SB/해비치_급식App_화면기획서_v0.5.3.html`
- 대상: 임직원 사용자 화면
- 제외: `PUBLISH/Admin` 어드민 화면
- HTML의 샘플 데이터와 `resources/js/common.js`의 임시 동작은 실제 API·인증·세션 로직으로 교체한다.

## 3. 반드시 유지할 구현 원칙

### 하단 탭바

개발 의견을 반영하여 탭바는 `position: fixed` 방식이 아니다.

```text
.page (flex column)
├─ header (필요한 화면만)
├─ .content (flex: 1 + 내부 스크롤)
└─ .tabbar (일반 흐름 요소)
```

- `.page`는 화면 높이를 가진 flex column 컨테이너다.
- `.content`만 `overflow-y: auto`로 스크롤한다.
- `.tabbar`는 페이지 하단 흐름 요소로 유지한다.
- 모바일 WebView 키보드·안전영역 이슈를 줄이기 위한 구조이므로 fixed 탭바로 되돌리지 않는다.
- My·식단 상세·약관 등 하위 화면은 탭바를 노출하지 않는다.

### 테마 / 브랜드 컬러

- 회사별 관리 값은 `--brand-primary` 1개다.
- 실제 값은 `resources/css/theme-*.css`에서 설정한다.
- 컴포넌트는 `--brand-primary`, `--brand-primary-light`, `--brand-primary-bg` 토큰만 사용한다.
- `?theme=haevichi`는 퍼블리싱 비교용 임시 테마 전환이다. 서비스에서는 로그인한 사용자의 회사 기준으로 테마 값을 적용한다.

## 5. 퍼블리싱 JS 처리 원칙

`resources/js/common.js`는 각 화면의 요소 존재 여부를 먼저 확인한 뒤 해당 화면 로직만 실행한다.

- `MEALS`, `DATE_MEAL_STATUS`, 공지·의견 샘플값은 API 데이터로 교체한다.
- `window.location.href` 기반 이동은 데모용이다. 개발 라우팅 방식에 맞게 교체한다.
- 가입 인증번호, 비밀번호 확인, 탈퇴 처리는 실제 보안 검증을 수행하지 않는다.
- 회원가입·비밀번호 변경의 단계형 UX는 유지하되, 브라우저 뒤로가기를 지원한다면 단계 상태를 History API 또는 라우터 상태와 연동한다.

## 8. 구현 시 유의사항

- 회원가입 허용 도메인과 이메일 인증은 반드시 서버에서 검증한다.
- 비밀번호 변경·회원 탈퇴는 프런트 입력값만으로 처리하지 않고 인증된 사용자·현재 비밀번호를 서버에서 검증한다.
- 개인정보처리방침의 예시 버전/본문은 정식 고지용 데이터가 아니다. 배포 전에 확정 문안으로 교체한다.
- 새 하위 화면을 추가할 때에는 탭바 노출 여부를 화면 뎁스 기준으로 검토한다. 1뎁스(홈/나의 의견/공지/My)만 탭바를 사용한다.
