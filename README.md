# 해비치 급식 App — PUBLISH 작업 폴더 안내

이 폴더는 해비치 급식 App(임직원 채널, 현대캐피탈 1차 적용)의 **디자인 시안 검토**와 **퍼블리싱 구조 검증**을 함께 관리하는 작업 공간입니다.

- 시작 지점: [`index.html`](index.html) — 브라우저로 열면 아래 두 영역으로 바로 이동할 수 있는 허브 페이지입니다.
- 실제 최종 결과물이 아니라, 방향을 정하기 위한 **중간 산출물**입니다.

## 폴더 구조

```
PUBLISH/
├─ index.html              작업 허브 (시안 3개 + 퍼블리싱 구조 링크)
├─ README.md                이 문서
├─ DESIGN Concept/          디자인 시안 3벌 (시각 검토용, 서로 독립적)
│  ├─ 시안 1번/
│  ├─ 시안 2번/
│  └─ 시안 3번/
├─ Admin/                   관리자 화면 퍼블리싱
├─ Front/                   임직원 사용자 화면 퍼블리싱
└─ Structure/               퍼블리싱 파일 구조 초안 (코드 구조 검토용)
   ├─ login.html · home.html · menu-detail*.html
   └─ resources/css · resources/js · resources/images
```

## 1. DESIGN Concept — 디자인 시안 3벌

**목적**: 화면 코드 구조와 무관하게, "실제 서비스 화면이 어떻게 보일지"를 비교하기 위한 시각 시안입니다. 홈 화면과 식단상세 화면(제육볶음 정식 기준)을 각 컨셉별로 만들었고, 모두 동일하게 하루 중 발생할 수 있는 7개 상태(조식전 ~ 석식후)를 검토할 수 있는 상태 미리보기 기능을 갖고 있습니다.

각 폴더의 `DESIGN_CONCEPT.md`에 해당 시안의 방향, 유지할 원칙, 상태별 동작 규칙이 상세히 정리되어 있습니다. 이후 어느 시안(또는 조합)으로 확정하든, 그 문서가 실제 개발 반영 시 기준 문서가 됩니다.

| 시안 | 한 줄 방향 |
| --- | --- |
| `시안 1번` | 오늘의 식사를 카드 우선순위로 안내하는 홈 — 조식·중식·석식 고정 순서 안에서 현재/다음 식사만 확장 카드로 강조 |
| `시안 2번` | 시간 흐름을 한눈에 보여주는 식단 보드 — 날짜 이동 + 세로 타임라인으로 진행 위치를 명확히 전달 |
| `시안 3번` | 사진 중심의 오늘의 한 끼 안내 — 현재/다음 식사를 큰 이미지와 짧은 안내 문구의 매거진형 히어로 카드로 강조 |

## 2. Structure — 퍼블리싱 파일 구조

**목적**: 디자인이 아니라 **코드 구조**(파일 구성, 폴더 규칙, 리소스 관리 방식)를 검증하기 위한 초안입니다. 화면 4개(로그인 → 홈 → 식단상세 평가전 → 식단상세 평가완료, 중식 평가완료 포함 5개)만 우선 만들어 개발팀 리뷰를 받았습니다.

- `resources/css/reset.css` + `style.css`: 리셋과 서비스 스타일 분리
- `resources/js/common.js`: 전체 페이지 공통 스크립트(페이지별 블록을 주석으로 구분)
- `resources/images/icon`, `resources/images/menu`: 타입별 이미지 폴더
- 화면은 페이지별 flat html 1개씩 — 실제 개발팀에 그대로 전달 가능한 구조를 목표로 함

개발팀 피드백(하단 탭바 `position:fixed` → flex 레이아웃 구조 전환 등)은 아직 이 폴더에 반영 전이며, 회신을 받은 뒤 구조를 확정합니다.

## 3. Front — 임직원 사용자 화면 퍼블리싱

`Front/`는 해비치 요구사항과 개발팀 피드백을 반영한 임직원 사용자 화면 퍼블리싱입니다. 개발 전달용 구조와 구현 원칙은 해당 폴더의 `README.md`를 참고하세요.

## 4. 앞으로의 진행 방식

1. 디자인 시안 3벌 중 방향 확정 (또는 요소별 조합)
2. 확정된 디자인 방향 + 개발팀 피드백 반영한 Structure 구조를 합쳐서 실제 화면 작업 시작
3. 실제 작업물이 생기면 별도 폴더(예: `Build/` 또는 확정 버전 폴더명)로 매핑하고, `index.html` 허브에 해당 폴더로 가는 링크를 추가
4. 화면이 늘어날 때마다 같은 방식으로 `index.html`만 갱신

즉 `index.html`은 앞으로도 "지금 이 프로젝트에 뭐가 있는지" 보여주는 진입점 역할을 계속 하고, 실제 산출물은 폴더 단위로 늘어나는 구조입니다.
