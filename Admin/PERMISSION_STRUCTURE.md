# 관리자 권한·조회범위 구조 — 수정 방향 기획

작성일: 2026-09-02 / 갱신: 2026-09-02
상태: **퍼블리싱 구조는 반영 완료.** 아래 4단계 권한·전역 전환 UI는 실제 운영 정책이 아니라 "화면이 이런 구조로 동작한다"는 것을 보여주기 위한 **예시/가정**이다. 실제 운영 시 등급 구성, 기업-사업장 소속 방식(예: 사업장을 기업 경계 없이 공통 관리자가 운영)은 달라질 수 있다. 그 경우에도 이 문서의 UI 골격(기업 select → 사업장 select 캐스케이딩 모달, `admin-common.js`의 `SCOPE_DATA` 설정)은 데이터 구조만 바꾸면 재사용 가능하도록 만들었다.

## 1. 문제 제기

현재 관리자 화면(대시보드/식단/코너/고객의견/공지) 5개가 각자 상단에 `기업 선택` + `사업장 선택` select를 독립적으로 갖고 있다. 화면마다 값이 따로 놀아서, 한 화면에서 사업장을 바꿔도 다른 화면으로 이동하면 초기화된다. 또한 이 select들은 "관리자가 어떤 권한이든 전체 기업/사업장을 다 고를 수 있다"는 전제로 만들어져 있는데, 실제로는 관리자 등급에 따라 조회 가능한 범위가 다르다.

## 2. 권한 4단계 초안

| 등급 | 주체 | 범위 | 기업/사업장 select |
| --- | --- | --- | --- |
| **시스템** | 우리(SK엠앤서비스) | 관리자 시스템 자체의 뼈대 — 권한관리(등급·역할 정의), 메뉴관리(관리자 메뉴 구성) 등 순수 시스템성 메뉴. **향후 확장 기능**, 현재 MVP 화면엔 없음 | 전체 고객사·사업장 자유 전환 (시스템 메뉴는 애초에 기업/사업장 개념이 없을 수도 있음) |
| **해비치** | 해비치(급식 서비스 운영사) | 운영에 필요한 시스템 설정 전부 — 고객사·사업장 생성, **인증 도메인**, 테마 관리 등. 시스템 등급의 메타 메뉴(권한관리/메뉴관리)만 제외 | 전체 고객사·사업장 자유 전환 |
| **회사 총괄** | 고객사(예: 현대캐피탈) 전체 담당자 | 해당 고객사 산하 전체 사업장 통합 조회/운영 | 그 고객사 안에서 **사업장만** 전환 가능. 기업은 고정 |
| **회사 운영** | 개별 사업장 담당자 | 자기 사업장만 | 기업·사업장 둘 다 고정 표시, 선택 불가 |

T Crew 계정 권한 분리 기획서(`SB/103_T Crew_계정 권한 분리_v0.7.0_250729.pptx`)의 "본사관리자 > 본부관리자 > 팀관리자 > 대리점총괄관리자" 위계와 유사하되, 해비치는 "운영사(해비치)"와 "개발사(시스템)"가 최상위에 이원으로 존재한다는 점이 다르다.

**주의 (2026-09-02 갱신):** 이 4단계·"기업 고정 = 회사 총괄" 매핑은 하나의 예시 시나리오다. 실제로는 "사업장을 기업 경계 없이 넘나드는 공통 운영 관리자"처럼 다른 소속 방식이 나올 수 있고, 등급 자체가 더 늘거나 줄 수도 있다. 아래 3번 UI는 이 표의 특정 등급 전제(회사 총괄 = 기업 고정)가 아니라 **"기업을 고르면 그에 속한 사업장만 보인다"는 더 일반적인 캐스케이딩 구조**로 만들어서, 등급 규칙이 바뀌어도 UI 골격은 재사용되게 했다.

## 3. 전역 조회범위 전환 UI — 반영 완료

화면마다 개별 select를 두는 대신, **상단바에 전역 컨트롤 하나**를 두는 방식으로 5개 화면(대시보드/식단/코너/고객의견/공지)에 모두 반영했다.

- 상단바 프로필 영역의 "기업 · 사업장" 텍스트를 클릭 가능한 버튼(`#scopeTrigger`)으로 변경
- 클릭 시 모달(`#scopeModal`)이 열리고, **기업 select(`#scopeCompany`) → 사업장 select(`#scopeSiteList`, 라디오)** 순으로 캐스케이딩 — 기업을 바꾸면 그 기업에 속한 사업장 목록으로 다시 그려진다
- 사업장 목록은 `resources/js/admin-common.js`의 `SCOPE_DATA` 객체(기업명 → 사업장 배열)에서 가져온다. 현재는 `현대캐피탈: [본사, 여의도, 홍대]` 하나뿐이지만, 고객사가 늘면 이 객체에 항목만 추가하면 됨
- "변경" 확정 시 상단바 라벨과 모든 화면 하단 필터 조건이 이 값을 기준으로 조회된다는 전제로 동작(실제 재조회 로직은 데모 토스트로만 표현)
- 위 2번 표의 "등급별로 기업 select를 숨기거나 고정한다"는 부분은 **아직 반영하지 않음** — 지금은 모든 화면에서 기업·사업장을 둘 다 바꿀 수 있는 상태이고, 등급별 노출 차이는 실제 권한 모델이 확정된 뒤 별도로 반영한다

기존에 화면 6개에 반복되던 개별 `기업 선택`/`사업장 선택` select 마크업은 모두 제거하고, 이 전역 컨트롤 하나로 흡수했다.

## 4. 화면별 영향 범위

| 화면 | 상태 |
| --- | --- |
| 대시보드 | 반영 완료 — 개별 select 제거, 전역 컨트롤로 교체 |
| 주간 식단 관리 | 반영 완료 — select만 전역으로 이동, 시작일·종료일 조건은 화면에 유지 |
| 코너 관리 | 반영 완료 — 전역 값 참조. "사업장 단위 코너 On/Off"는 그대로 동작 |
| 별점 통계 | [0.6.7 반영] 별점 기능 삭제 확정으로 화면 자체를 삭제(결번 처리) |
| 고객의견 | 반영 완료 — select만 전역으로 이동, 상태·유형 조건은 화면에 유지 |
| 공지 관리 | 반영 완료 — 전역 값 참조 |
| (향후) 인증 도메인 관리 | 미작업. 기업 단위 설정이라 전역 컨트롤의 "기업" 값과 연동 예정 |
| (향후) 계정 관리 | 미작업. 등급별 조회 범위 제한 필요 (아래 5번 참고, 미확정) |
| (향후) 사업장·테마 관리 | 미작업(nav에 링크만 존재). 사업장 자체를 정의하는 화면 |
| (향후) 관리자 계정·권한 관리 | 미작업. 등급 체계 자체를 다루는 화면 |

## 5. 계정 생성/조회 권한 규칙 (제안, 미확정)

T Crew 패턴처럼 "본인 등급 이하만 생성·조회 가능" 원칙을 적용하는 방향을 제안한다.

- 시스템: 전체 등급 계정 생성/조회 가능 (해비치 계정 포함)
- 해비치: 회사 총괄·회사 운영 계정 생성/조회 가능. 시스템·해비치 등급 계정은 생성 불가(또는 시스템만 가능)
- 회사 총괄: 같은 기업 산하 회사 운영 계정만 생성/조회 가능
- 회사 운영: 계정 관리 화면 접근 불가 (본인 계정 정보 수정만 가능)

## 6. 미확정 사항

1. 관리자 계정 생성 권한의 정확한 상하 규칙 (5번 제안이 맞는지)
2. 인증 도메인 관리를 회사 총괄도 볼 수 있게 할지, 해비치 이상으로 제한할지
3. 시스템 등급의 "권한관리/메뉴관리" 실제 화면 설계 — 현재는 개념만 있고 화면 없음
4. 전역 컨트롤의 정확한 UI 형태(팝업 vs 드롭다운 vs 별도 페이지)와 위치
5. 로그인 시 등급을 어떻게 판별하는지(계정에 등급이 미리 매핑되어 있다는 전제로 보임 — 로그인 화면 자체 변경은 범위 밖)

## 7. 다음 단계

퍼블리싱 구조(전역 기업→사업장 캐스케이딩 select)는 현재 수준으로 충분하다고 보고 마무리한다. 이후 실제 반영이 필요한 것은:

1. 실제 운영 등급·소속 방식이 확정되면, 이 문서의 4단계 표와 `SCOPE_DATA` 데이터 구조를 그 결과에 맞게 다시 정리
2. 등급별로 기업 select 자체를 숨기거나 고정할지는 그때 별도로 반영 (지금은 모든 화면에서 기업·사업장 둘 다 바꿀 수 있는 상태로 둠)
3. 인증 도메인/계정/사업장·테마/관리자 권한 화면을 새로 만들 때, 이 전역 컨트롤과 어떻게 연동할지는 각 화면 작업 시점에 다시 확인
