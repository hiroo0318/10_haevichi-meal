# 관리자 권한·조회범위 구조 — 수정 방향 기획

작성일: 2026-09-02 / 갱신: 2026-09-03
상태: **최상위 구조(0번) 확정, 퍼블리싱에 순차 반영 중.** 아래 4단계 권한 자체는 여전히 예시/가정이지만, 그 4단계가 화면 레벨에서 어떻게 나뉘는지는 0번 섹션으로 확정했다.

## 0. 최상위 3분할 구조 (확정)

관리자 화면은 사이드 메뉴가 아니라 **최상단에서 시스템/해비치 등급에게만 보이는 3분할 스위처**로 나뉜다. 회사 총괄·회사 운영 등급은 이 스위처 자체가 보이지 않고, 지금까지처럼 "운영 관리" 하나만 쓰는 것처럼 보인다.

| 구분 | 내용 | 회사 컨텍스트 | 접근 가능 등급 |
| --- | --- | --- | --- |
| **회사 관리** | 회사 자체를 등록/수정. 회사 생성 시 그 회사의 첫 운영자(회사총괄)를 함께 배정 | 없음 — 전체 회사 대상, 상단 회사 선택과 무관 | 시스템, 해비치 |
| **시스템 관리** | 시스템·해비치 등급 관리자 계정 관리. 향후 메뉴관리·권한관리 신설 예정 | 없음 — 시스템/해비치 등급은 애초에 회사에 속하지 않음 | 시스템 (해비치는 TBD) |
| **운영 관리** | 지금까지 만든 모든 화면(대시보드/식단/고객의견/공지 + 인증도메인/계정관리/사업장·테마/운영자 관리) | 상단에서 회사 선택 후 그 안에서 동작 | 시스템, 해비치, 회사 총괄, 회사 운영 |

이 구조로 이전에 논의하던 문제들이 풀린다:

- **사업장·테마 관리**: 사업장은 회사에 종속된 리소스라, "운영 관리" 안에서 회사 선택 후 사업장 추가만 하면 된다. 전체 회사를 넘나드는 별도 뷰가 필요 없다.
- **관리자 계정 관리**: 시스템·해비치 등급은 회사에 속하지 않아 "회사를 선택하고 그 안의 관리자를 본다"는 구조로 관리할 수 없다. 그래서 이 등급 관리자 계정은 **"시스템 관리"**로 빠지고, 회사에 속한 관리자(회사총괄·회사운영)는 "운영 관리 > 환경설정"에 남되 **이름을 "관리자 계정·권한"에서 "운영자 관리"로 변경**한다 — 그 회사의 운영자를 지정하는 화면이라는 의미를 명확히 하기 위함.

## 1. 문제 제기

현재 관리자 화면(대시보드/식단/코너/고객의견/공지) 5개가 각자 상단에 `기업 선택` + `사업장 선택` select를 독립적으로 갖고 있다. 화면마다 값이 따로 놀아서, 한 화면에서 사업장을 바꿔도 다른 화면으로 이동하면 초기화된다. 또한 이 select들은 "관리자가 어떤 권한이든 전체 기업/사업장을 다 고를 수 있다"는 전제로 만들어져 있는데, 실제로는 관리자 등급에 따라 조회 가능한 범위가 다르다.

## 2. 권한 4단계 초안

| 등급 | 주체 | 범위 | 기업/사업장 select |
| --- | --- | --- | --- |
| **시스템** | 우리(SK엠앤서비스) | 관리자 시스템 자체의 뼈대 — 권한관리(등급·역할 정의), 메뉴관리(관리자 메뉴 구성) 등 순수 시스템성 메뉴. **향후 확장 기능**, 현재 MVP 화면엔 없음 | 전체 고객사·사업장 자유 전환 (시스템 메뉴는 애초에 기업/사업장 개념이 없을 수도 있음) |
| **해비치** | 해비치(급식 서비스 운영사) | 운영에 필요한 시스템 설정 전부 — 고객사·사업장 생성, **인증 도메인**, 테마 관리 등. 시스템 등급의 메타 메뉴(권한관리/메뉴관리)만 제외 | 전체 고객사·사업장 자유 전환 |
| **회사 총괄** | 고객사(예: 현대캐피탈) 전체 담당자 | 해당 고객사 산하 전체 사업장 통합 조회/운영 | 그 고객사 안에서 **사업장만** 전환 가능. 기업은 고정 |
| **회사 운영** | 개별 사업장 담당자 | 자기 사업장만 | 기업·사업장 둘 다 고정 표시, 선택 불가 |

T Crew 계정 권한 분리 기획서(`SB/103_T Crew_계정 권한 분리_v0.7.0_250729.pptx`)의 "본사관리자 > 본부관리자 > 팀관리자 > 대리점총괄관리자" 위계와 유사하되, 해비치는 "운영사(해비치)"와 "개발사(시스템)"가 최상위에 이원으로 존재한다는 점이 다르다.

**주의 (2026-09-02 갱신):** 이 4단계·"기업 고정 = 회사 총괄" 매핑은 하나의 예시 시나리오다. 실제로는 "사업장을 기업 경계 없이 넘나드는 공통 운영 관리자"처럼 다른 소속 방식이 나올 수 있고, 등급 자체가 더 늘거나 줄 수도 있다. 아래 3번 UI는 이 표의 특정 등급 전제(회사 총괄 = 기업 고정)가 아니라 **"기업을 고르면 그에 속한 사업장만 보인다"는 더 일반적인 캐스케이딩 구조**로 만들어서, 등급 규칙이 바뀌어도 UI 골격은 재사용되게 했다.

## 3. 조회범위 전환 UI — 상단 "기업"만, 사업장은 화면별로 재설계 (반영 완료)

**배경**: 처음엔 상단 전역 컨트롤에서 기업→사업장을 한 번에 캐스케이딩 선택하는 구조로 반영했으나, 다음 두 가지가 확인되면서 구조를 바꿨다.

1. 임직원 가입은 **회사 단위**이지 사업장 단위가 아니다. 즉 계정·인증도메인은 애초에 사업장 개념이 없다.
2. 화면마다 "사업장별로 나눠 관리"와 "회사 통합으로 관리"가 갈리는 필요가 다르다. 이걸 하나의 전역 사업장 선택자로 뭉뚱그릴 수 없었다.

**현재 구조**:

- 상단바에는 **기업만** 남긴다. `#scopeTrigger` 클릭 → `#scopeModal`에 기업 select(`#scopeCompany`) 하나만 있고, 사업장 select는 제거했다.
- 사업장이 필요한 화면은 **화면 안의 조회 조건에 사업장 select를 각자 둔다.** 화면 성격에 따라 옵션 구성이 다르다:

| 화면 | 사업장 처리 |
| --- | --- |
| 대시보드 | 전체(회사 합산) / 특정 사업장 — 둘 다 선택 가능 |
| 주간 식단 관리 | 특정 사업장 **필수 선택** (전체보기 없음 — 메뉴 자체가 사업장마다 다른 데이터라 합쳐 볼 수 없음) |
| 코너 관리 | 특정 사업장 **필수 선택** (식단 관리와 같은 이유 — 코너 구성이 사업장 고유값) |
| 고객의견 | 전체(회사 합산) / 특정 사업장 — 둘 다 선택 가능. 전체 선택 시 구분을 위해 목록에 사업장 컬럼 추가 |
| 공지 관리 | 조회 필터가 아니라 **등록/수정 시점의 속성** — "전체 노출" 또는 "특정 사업장(복수 선택 가능)"을 지정. 목록에 노출 대상 컬럼으로 표시 |
| 인증 도메인 / 계정 관리 / 탈퇴 사유 통계 | **사업장 없음.** 가입이 회사 단위라 원천적으로 사업장 구분이 의미 없음 — 관련 컬럼 자체를 뺐다 |
| 사업장 관리 | 사업장 자체를 다루는 화면이라 당연히 사업장 목록/추가/삭제/사용여부를 다룸. 다만 "사업장을 구분해서 운영할지" 자체를 상단 토글로 켜고 끌 수 있게 했다 |
| 테마 관리 | **사업장 없음.** 대표 색상 하나가 회사 전체 톤앤매너를 결정하므로 항상 회사 통합 관리 |
| 운영자 관리 | 사업장 없음(예정) |

기존에 있던 `resources/js/admin-common.js`의 `SCOPE_DATA`(기업→사업장 캐스케이딩)와 사업장 라디오 렌더링 로직은 제거하고, 스코프 모달은 기업 select 하나만 남겼다.

## 4. 화면별 영향 범위

| 화면 | 상태 |
| --- | --- |
| 대시보드 | 반영 완료 — 화면 안에 사업장 select(전체/본사/여의도/홍대) |
| 주간 식단 관리 | 반영 완료 — 화면 안에 사업장 select(필수, 전체 없음) |
| 코너 관리 | 반영 완료 — 화면 안에 사업장 select(필수, 전체 없음) |
| 별점 통계 | [0.6.7 반영] 별점 기능 삭제 확정으로 화면 자체를 삭제(결번 처리) |
| 고객의견 | 반영 완료 — 화면 안에 사업장 select(전체/특정), 전체 선택 대비 목록에 사업장 컬럼 추가 |
| 공지 관리 | 반영 완료 — 등록/수정 모달에 노출 대상(전체/특정 사업장 복수선택) 필드 추가, 목록에 노출 대상 컬럼 추가 |
| 인증 도메인 설정 | 반영 완료(`domain.html`) — 사업장 없음, 회사 단위 도메인 목록 |
| 계정 관리 / 탈퇴 사유 통계 | 반영 완료(`account.html`/`withdrawal.html`) — 사업장 없음(가입이 회사 단위라 계정에 사업장 속성 자체가 없음) |
| 사업장 관리 / 테마 관리 | 반영 완료(`site.html`/`theme.html`). 사업장 관리는 "사업장 구분 사용" 상단 토글로 사업장 목록(추가/삭제/사용여부) 관리 여부 자체를 켜고 끔. 테마는 사업장 없음, 회사 통합 |
| (향후) 운영자 관리 (구 "관리자 계정·권한") | 운영 관리 소속으로 확정, 명칭 변경 예정. 회사에 속한 운영자(회사총괄/회사운영)만 다루며, 시스템·해비치 등급 계정은 "시스템 관리"로 분리 |
| (향후) 회사 관리 | 0번 섹션 참고 — 시스템/해비치 전용 최상위 메뉴, 미작업 |
| (향후) 시스템 관리 | 0번 섹션 참고 — 시스템(해비치는 TBD) 전용 최상위 메뉴, 미작업 |

## 5. 계정 생성/조회 권한 규칙 (제안, 미확정)

T Crew 패턴처럼 "본인 등급 이하만 생성·조회 가능" 원칙을 적용하는 방향을 제안한다.

- 시스템: 전체 등급 계정 생성/조회 가능 (해비치 계정 포함)
- 해비치: 회사 총괄·회사 운영 계정 생성/조회 가능. 시스템·해비치 등급 계정은 생성 불가(또는 시스템만 가능)
- 회사 총괄: 같은 기업 산하 회사 운영 계정만 생성/조회 가능
- 회사 운영: 계정 관리 화면 접근 불가 (본인 계정 정보 수정만 가능)

## 6. 미확정 사항

1. 관리자 계정 생성 권한의 정확한 상하 규칙 (5번 제안이 맞는지)
2. 인증 도메인 관리를 회사 총괄도 볼 수 있게 할지, 해비치 이상으로 제한할지
3. 시스템 등급의 "권한관리/메뉴관리" 실제 화면 설계 — 현재는 개념만 있고 화면 없음
4. 전역 컨트롤의 정확한 UI 형태(팝업 vs 드롭다운 vs 별도 페이지)와 위치
5. 로그인 시 등급을 어떻게 판별하는지(계정에 등급이 미리 매핑되어 있다는 전제로 보임 — 로그인 화면 자체 변경은 범위 밖)

## 7. 다음 단계

퍼블리싱 구조(전역 기업→사업장 캐스케이딩 select)는 현재 수준으로 충분하다고 보고 마무리한다. 이후 실제 반영이 필요한 것은:

1. 실제 운영 등급·소속 방식이 확정되면, 이 문서의 4단계 표와 `SCOPE_DATA` 데이터 구조를 그 결과에 맞게 다시 정리
2. 등급별로 기업 select 자체를 숨기거나 고정할지는 그때 별도로 반영 (지금은 모든 화면에서 기업·사업장 둘 다 바꿀 수 있는 상태로 둠)
3. 인증 도메인/계정/사업장·테마/관리자 권한 화면을 새로 만들 때, 이 전역 컨트롤과 어떻게 연동할지는 각 화면 작업 시점에 다시 확인
