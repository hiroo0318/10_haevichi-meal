# 해비치 급식 App — 관리자 퍼블리싱

관리자 채널(PC 웹)의 화면 구조와 공통 UI를 검토·확장하기 위한 퍼블리싱 작업 폴더다. 임직원용 모바일 화면의 `PUBLISH/Structure/`와 자원·스타일을 공유하지 않으며, 관리자 전용 CSS·JS·이미지를 이 폴더 안에서 관리한다.

## 기준 자료

- 최신 화면기획서: `SB/해비치_급식App_화면기획서_v0.5.3.html` (2026-09-01)
- 관리자 디자인 가이드: [`HAEVICHI_DESIGN.md`](HAEVICHI_DESIGN.md)
- 프로젝트 범위와 결정: `.codex/PROJECT_CONTEXT.md`, `.codex/DECISIONS.md`

화면기획서와 이전 산출물이 충돌하면 v0.5.3을 우선 적용한다. v0.5.3은 기존 기능 범위를 유지하며, 관리자 채널에서는 `VOC`를 **고객의견**으로 통일한다.

## 공통 UI 원칙

- PC 웹을 기준으로 `상단바 + 좌측 네비게이션 + 콘텐츠 영역`을 공통 레이아웃으로 사용한다.
- 페이지 상단은 **페이지 타이틀만 노출**한다. 영문 레이블, 설명문, 화면 ID, 기준 시간은 화면에 표시하지 않는다.
- 기업과 사업장은 항상 별도 조회 조건으로 둔다.
- 2뎁스 메뉴는 본문 탭이 아니라 좌측 네비게이션의 서브 메뉴로 구성한다.
- 버튼은 클릭 가능한 조작 요소로 명확히 보이도록 테두리·배경·호버 상태를 적용한다.
- 폰트는 현재 시스템 폰트 스택을 사용한다. 외부 웹폰트나 폰트 파일은 별도 결정 전까지 추가하지 않는다.
- [결정] 검색 결과 목록이 여러 건일 수 있는 화면(주간 식단 관리, 고객의견, 공지 관리)은 공통 페이지네이션 컴포넌트를 사용한다. "이미지 미등록만 보기"·"답변대기만 보기" 같은 빠른 필터 칩이 켜져 있을 때는 페이지 구분 없이 조건에 맞는 행을 전부 보여준다.

## 화면별 운영 규칙

### 관리자 로그인 — HVM-BO-01-00

- 관리자 ID·비밀번호 입력 후 로그인. 임직원 로그인(사내 메일+비밀번호)과 별도의 관리자 계정 체계이며, 계정 발급·권한 부여는 관리자 계정·권한 화면(HVM-BO-10-00, 미작업)에서 관리한다.
- 로그인 성공 시 권한별 메뉴가 노출되며 대시보드로 이동한다. 이 퍼블리싱 단계에서는 실제 인증 없이 ID·비밀번호 값만 확인하고 바로 `dashboard.html`로 이동하는 데모 동작이다.
- [결정] ID·비밀번호 관련 안내(미입력 등)는 우측 하단 토스트가 아니라 **해당 인풋 바로 아래 얼럿 문구**로 노출한다. 토스트는 시스템 오류 안내에만 사용하고, 입력값 검증은 필드 단위로 즉시 확인할 수 있게 분리했다.
- 사이드바·상단바가 없는 단독 화면이며, PC 웹 기준으로 개발한다.

### 대시보드 — HVM-BO-02-00

- 고객의견 미처리 건수, 누적 가입자 수를 제공한다. [0.6.7 반영] 별점 기능 삭제(요청사항.pdf 반영)에 따라 평균 별점 지표는 삭제했다.
- 식수(이용 인원) 현황은 제공하지 않는다.
- `신규 가입자 수`는 기획서상 제안/TBD이므로 기본 지표로 확정하지 않는다.

### 주간 식단 관리 — HVM-BO-03-00

- 식단 등록·수정은 엑셀 업로드 방식으로만 처리한다. 개별 등록·수정 폼은 제공하지 않는다.
- 조회 조건은 기업, 사업장, 시작일, 종료일로 구성한다.
- 업로드 양식의 필수 컬럼은 `일자`, `사업장`, `식사구분`, `코너명`, `메뉴명`이다.
- 코너명은 필수이며 코너 관리에 등록된 값과 일치해야 한다. 코너 구분이 없는 식사도 기본 코너명(예: `단일`)을 사용한다.
- 이미지가 없는 행에는 이미지 등록 버튼을 제공한다. 메뉴 데이터 변경은 엑셀 재업로드로, 이미지 보완은 해당 행에서 처리한다.
- 업로드 오류는 별도 결과 페이지 없이 행 번호·컬럼명·오류 사유로 안내한다.
- [0.6.7 반영] 목록에 게시상태(노출/임시저장), 상태(등록완료/미등록) 컬럼을 노출해 등록은 되어 있으나 사용자 화면에는 아직 노출하지 않은 건을 구분할 수 있게 한다.
- [결정] 메뉴 이미지가 미등록인 행은 게시상태 토글 자체를 조작 불가(disabled) 상태로 잠가둔다. 단순히 눌러도 안 바뀌는 게 아니라 토글이 흐리게 표시되어 조작할 수 없다는 게 시각적으로 드러나야 한다. 이미지를 등록하면 그 즉시 토글이 풀려 노출로 전환할 수 있다.

### 코너 관리 — HVM-BO-03-02

- [0.5.5 반영] 식단 관리의 좌측 네비게이션 2뎁스 메뉴로 제공한다.
- 사업장별로 **5개 슬롯(코너A~코너E)을 기본 제공**하며, 코너명만 수정 가능하다. 코너 추가/삭제 기능은 없다(0.5.4에서 삭제됨).
- **코너 사용 여부는 사업장 단위 On/Off**로 제어한다(코너별 개별 On/Off가 아니다).
- 코너 사용 On 상태에서는 식단 업로드 양식의 코너명이 필수이며, 이 화면에 등록된 코너명을 기준으로 검증한다.
- 코너 사용 Off 상태에서는 코너명이 선택 입력값이며, 미입력 시 단일 메뉴로 처리한다.
- On/Off 전환은 **이후 신규 업로드 검증 기준에만 적용**되며, 과거에 등록된 식단 데이터는 소급 변경하지 않는다.
- [퍼블리싱 참고] 텍스트명을 내부적으로 코드ID로 매핑해 저장하는 방식은 실제 개발 단계의 데이터 모델 논의이며, 퍼블리싱(화면)에는 반영하지 않는다 — 화면은 여전히 코너명(텍스트) 기준으로 동작한다.

### 별점 통계 — HVM-BO-04-00 (결번, 화면 삭제됨)

- [0.6.7 반영, 확정] 별점 기능 삭제(요청사항.pdf 반영)에 따라 HVM-BO-04-00은 결번 처리하며 사이드바에도 노출하지 않는다. `rating.html`과 관련 리소스(`admin-common.js`의 페이지네이션 초기화, `admin.css`의 `.rating-table` 스타일)를 삭제했다.
- 기존 별점 관련 정책(1인 1회 평가, 재평가 불가, 최대 5개 표시 등)은 모두 폐기한다.
- 임직원 화면의 "이 메뉴에 대한 의견을 남겨주세요" 영역은 별점 대신 '의견 쓰기' 버튼으로 대체된다(관리자 화면 범위 밖, 참고용).

### 고객의견 — HVM-BO-05-00

- 기존 명칭 `VOC 처리`는 고객의견으로 통일한다.
- [결정] 상태값은 `답변대기 → 답변완료` 2단계로 사용한다. 조회 조건은 기업·사업장·상태·유형이다.
  - [기획서 명시]는 정책 문구 기준 `접수 → 처리중 → 완료` 3단계였으나(같은 문서의 정적 목업은 `답변대기`/`답변완료` 2단계 배지를 사용해 문서 내에서도 서로 달랐음), 2단계(`답변대기`/`답변완료`)로 쓰기로 확정했다.
- 유형은 맛/메뉴, 위생, 서비스/친절도, APP 사용 경험, 기타를 제공한다.
- [결정] 목록은 접수일·작성자·유형·내용·첨부·상태 요약만 보여주고, 행을 클릭하면 레이어 팝업(모달)에서 접수 내용 전체·첨부 이미지(복수 가능)·답변 작성/열람을 처리한다. 목록에 접수 내용·답변 입력을 함께 쌓아두는 3단 세로 구조는 목록이 길어질수록 레이아웃이 밀리는 문제가 있어 모달 방식으로 확정했다.
- 답변대기 건을 클릭하면 모달에서 답변을 작성하고, 등록 시 상태가 답변완료로 바뀐다. 답변완료 건은 모달에서 등록된 답변을 읽기 전용으로 보여준다.
- 작성자는 메일 주소 일부를 마스킹해 표시한다(마스킹 규칙은 기획서상 TBD).
- 첨부 이미지는 1장이든 여러 장이든 모달 안에 썸네일로 나열하고, 클릭하면 큰 미리보기(라이트박스)로 확인한다.
- [0.6.7 반영] "원본 다운로드 기능 제공" 확정사항은 별도 다운로드 버튼 없이 충족한다. 미리보기가 일반 `<img>` 태그라 마우스 우클릭 → "이미지를 다른 이름으로 저장"으로 브라우저 기본 기능만으로 원본을 받을 수 있다.

### 공지 관리 — HVM-BO-06-00

- 공지 등록/수정은 고객의견과 같은 레이어 팝업(모달) 방식으로 통일했다(원문 목업은 목록 하단 인라인 패널이었으나, 이번에 확정한 "목록+모달" 공통 패턴을 그대로 적용).
- 등록 항목: 제목, 내용, 노출기간(시작~종료), 상단 고정 여부, 팝업 노출 여부(체크 시 별도 팝업 노출기간 입력).
- 목록은 제목·노출기간·상단고정·팝업노출·상태(노출중/종료)로 구성하며, 행을 클릭하면 같은 모달이 수정 모드로 열리고 삭제도 가능하다.
- [TBD, 기획서 명시] 상단고정 동시 등록 시 개수 제한 여부, 팝업 노출 대상이 여러 건일 때의 노출 순서·개수 제한은 기획서상 미확정 상태다. 이 화면은 제한 없이 데모로만 구현했다.

### 인증 도메인 설정 — HVM-BO-07-00

- [퍼블리싱 검토 반영] 상단 안내 박스 문구는 기획서 원문(v2 변경 핵심 설명)이 관리자 실무자에게 장황해서, "허용 도메인으로 등록된 메일 주소만 회원가입이 가능합니다. 등록되지 않은 도메인은 가입이 차단됩니다."로 단순화했다. 기획서 쪽 문구도 함께 수정이 필요하다.
- 등록 도메인 표는 사업장·허용 도메인·서브도메인 허용 여부·등록일로 구성하며, 도메인 추가는 별도 모달(사업장 선택·도메인 입력·서브도메인 허용 토글)로 처리한다. 개별 수정 기능은 없고 추가/삭제만 제공한다(기획서 요소 설명 기준).
- [결정] 도메인 삭제는 해당 도메인의 신규 가입을 즉시 차단하는 영향이 있어, 삭제 전 확인 모달(대상 사업장·도메인 명시)을 거치도록 했다. 네이티브 `confirm()`은 임베디드 미리보기 환경에서 신뢰할 수 없어 쓰지 않는다(게시상태 토글과 동일한 방침).
- 화면 하단에 "명부 삭제에 따른 유의 사항"(퇴사자 미차단, 사번 미검증, 협력사·파견 인력 이용 불가) 3개 항목을 상시 경고 박스로 노출한다.
- [퍼블리싱 참고] 기획서 원문 표의 "사업장" 컬럼 예시값이 회사명(현대캐피탈)으로 되어 있으나, 다른 화면들이 이미 "사업장=본사/여의도/홍대" 체계로 통일돼 있어 그 체계를 그대로 따랐다. 기업 단위는 상단 전역 조회범위로 고정된다는 전제다.

## 유의 사항

- 실제 파일 업로드·엑셀 다운로드·데이터 저장은 이 퍼블리싱 단계에서 데모 동작으로만 표현한다.

- 고객의견·계정·사업장 데이터는 예시 값이며, 실제 개인정보를 넣지 않는다.
