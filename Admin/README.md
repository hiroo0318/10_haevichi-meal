# 해비치 급식 App — 관리자 퍼블리싱

관리자 채널(PC 웹)의 화면 구조와 공통 UI를 검토·확장하기 위한 퍼블리싱 작업 폴더다. 임직원용 모바일 화면의 `PUBLISH/Structure/`와 자원·스타일을 공유하지 않으며, 관리자 전용 CSS·JS·이미지를 이 폴더 안에서 관리한다.

## 기준 자료

- 최신 화면기획서: `SB/해비치 급식 App-0.6.0.html` (2026-09-06) — 계정 관리(HVM-BO-08-00) 검색조건·상태값·상세 모달 개편분 반영. 그 외 화면은 아직 `SB/해비치 급식 App-0.5.11.html` (2026-09-03) 기준이다 — 이전에 "0.6.7"로 잘못 표기됐던 버전과 내용은 동일하고 버전 라벨만 정정된 파일이다.
- 관리자 디자인 가이드: [`HAEVICHI_DESIGN.md`](HAEVICHI_DESIGN.md)
- 프로젝트 범위와 결정: `.codex/PROJECT_CONTEXT.md`, `.codex/DECISIONS.md`

화면기획서와 이전 산출물이 충돌하면 최신 화면기획서를 우선 적용한다. 관리자 채널에서는 `VOC`를 **고객의견**으로 통일한다.

## 공통 UI 원칙

- PC 웹을 기준으로 `상단바 + 좌측 네비게이션 + 콘텐츠 영역`을 공통 레이아웃으로 사용한다.
- [2026-09-04 버그 수정] 좌측 네비 2뎁스 그룹(식단 관리/계정 관리/사업장·테마 관리)의 부모 라벨은 실제로는 아무 동작도 안 하는 `<div>`인데 클릭 가능한 링크와 똑같이 스타일링돼 있어서, 눌러도 반응이 없는 게 마치 오작동처럼 보였다. `<button>` 기반 **아코디언 토글**로 바꿔서 누르면 그 그룹만 접고 펴지게 했다. 기본값은 현재 페이지가 속한 그룹만 펼쳐지고 나머지는 접힌 상태다. 이 작업 중 `dashboard.html`의 사이드바가 예전 구조(식단 관리가 2뎁스 없이 `menu.html` 바로 링크)로 갱신이 안 돼 있던 것도 같이 발견해서 다른 화면들과 동일한 구조로 맞췄다.
  - [후속 수정] 처음엔 JS(`admin-common.js`)가 로드된 뒤에야 접어서, 새로고침 시 전체 메뉴가 펼쳐졌다가 순간 접히는 깜빡임(FOUC)이 있었다. `.nav-sub:has(.nav-sub-link.active)` CSS 규칙으로 **첫 페인트부터** 올바른 펼침/접힘 상태가 그려지도록 바꾸고, JS는 그 상태를 `is-open`/`is-closed` 클래스로 넘겨받아 이후 클릭 토글만 담당하게 했다.
- 페이지 상단은 **페이지 타이틀만 노출**한다. 영문 레이블, 설명문, 화면 ID, 기준 시간은 화면에 표시하지 않는다.
- [2026-09-03 개정] 상단바 전역 조회 범위는 **기업만** 다룬다. 사업장은 화면마다 필요 여부·방식이 달라 전역에서 빼고 각 화면 안의 조회 조건으로 내렸다. 자세한 화면별 처리는 "사업장 조회 범위 원칙" 섹션 참고.
- [2026-09-10 추가, 기획서(0.6.0 HVM-BO-02-00) 반영] 상단바 우측에 **기업 선택 · 관리자 정보 · 로그아웃**, 3개 버튼을 나란히 뒀다. 이전엔 "정혜림 관리자"가 클릭 안 되는 텍스트였고 로그아웃 버튼 자체가 없었다.
  - **관리자 정보**(정혜림 관리자) 클릭 → 관리자 ID·이름·권한·상태를 보여주는 모달, 그 안에 "비밀번호 변경"(기존 비밀번호 인증 → 신규 비밀번호 설정 2단계) 진입 버튼.
  - **로그아웃** 클릭 → `login.html`로 이동(데모라 별도 세션 처리는 없음).
  - 모든 화면 상단바에 동일하게 있는 컴포넌트라 다른 모달들과 달리 화면마다 마크업을 두지 않고, `admin-common.js`가 `#adminInfoTrigger` 버튼이 있는 화면에서 모달 DOM을 한 번만 만들어 붙이는 방식으로 처리했다.
- 2뎁스 메뉴는 본문 탭이 아니라 좌측 네비게이션의 서브 메뉴로 구성한다.
- 버튼은 클릭 가능한 조작 요소로 명확히 보이도록 테두리·배경·호버 상태를 적용한다.
- 폰트는 현재 시스템 폰트 스택을 사용한다. 외부 웹폰트나 폰트 파일은 별도 결정 전까지 추가하지 않는다.
- [결정] 검색 결과 목록이 여러 건일 수 있는 화면(주간 식단 관리, 고객의견, 공지 관리)은 공통 페이지네이션 컴포넌트를 사용한다. "이미지 미등록만 보기"·"답변대기만 보기" 같은 빠른 필터 칩이 켜져 있을 때는 페이지 구분 없이 조건에 맞는 행을 전부 보여준다.

## 사업장 조회 범위 원칙 (2026-09-03)

임직원 가입은 사업장이 아니라 **회사 단위**다(허용 도메인은 회사 전체 공통이며 사업장별로 나뉘지 않음). 그래서 계정에는 사업장 속성이 없고, 상단 전역 컨트롤도 기업만 남기고 사업장은 화면 성격에 맞게 각자 다르게 처리한다. 세부 근거는 `PERMISSION_STRUCTURE.md` 3번 섹션 참고.

## 화면별 운영 규칙

### 관리자 로그인 — HVM-BO-01-00

- 관리자 ID·비밀번호 입력 후 로그인. 임직원 로그인(사내 메일+비밀번호)과 별도의 관리자 계정 체계이며, 계정 발급·권한 부여는 관리자 계정·권한 화면(HVM-BO-10-00, 미작업)에서 관리한다.
- 로그인 성공 시 권한별 메뉴가 노출되며 대시보드로 이동한다. 이 퍼블리싱 단계에서는 실제 인증 없이 ID·비밀번호 값만 확인하고 바로 `dashboard.html`로 이동하는 데모 동작이다.
- [결정] ID·비밀번호 관련 안내(미입력 등)는 우측 하단 토스트가 아니라 **해당 인풋 바로 아래 얼럿 문구**로 노출한다. 토스트는 시스템 오류 안내에만 사용하고, 입력값 검증은 필드 단위로 즉시 확인할 수 있게 분리했다.
- 사이드바·상단바가 없는 단독 화면이며, PC 웹 기준으로 개발한다.

### 대시보드 — HVM-BO-02-00

- 고객의견 미처리 건수, 누적 가입자 수를 제공한다. [0.5.11 반영] 별점 기능 삭제(요청사항.pdf 반영)에 따라 평균 별점 지표는 삭제했다.

### 주간 식단 관리 v2 — HVM-BO-03-00 (현재 연결된 버전)

[2026-09-04 결정, 회의록 반영] 코너 관리 폐지에 따라 화면 구조를 완전히 재설계했다. 기존 `menu.html`(v1)은 그대로 두고 `menu-v2.html`을 새로 만들어 네비게이션만 이쪽으로 연결했다.

- **레이아웃**: 상단 툴바(사업장 select + 양식 다운로드 + 파일 업로드) → 범례 → 2주 달력(날짜 선택 + 상태 요약 통합) → 선택 날짜의 조식/중식/석식 관리 영역, 세로로 배치.
- [2026-09-07 재설계, 사용자 논의 반영] **월 달력 + "선택 주차" 7일 스트립의 2뎁스 구조를 하나로 합쳤다.** 기존엔 "달력에서 주차를 고르고 → 우측 스트립에서 날짜를 다시 고르는" 2단계였는데, 조/중/석 상태 점을 달력 칸 안에 바로 넣으면서 날짜 선택이 한 번의 클릭으로 끝나도록 바꿨다.
  - **2주(이번 주 + 다음 주) 기본 노출, 주 단위 이동**으로 바꿨다 — 실제로 필요한 범위가 이번 주~3, 4주 앞뒤 정도라 월 달력(6주치, 다른 달 날짜까지 항상 그림)은 과했다는 판단. `‹ ›`로 한 주씩 이동하고, "이번 주" 버튼으로 바로 복귀한다. 임의 월로 점프하는 기능은 없다(필요 범위 밖).
  - 날짜 칸에는 **숫자와 조/중/석 점 3개(세로 스택)를 같은 줄에 나란히** 배치했다 — 점을 숫자 아래 별도 줄에 넣으면 셀이 커져서 전체 높이가 늘어나므로, 숫자 옆에 얹는 방식으로 이전 레이아웃의 높이값(6줄 달력 + 스트립 1줄)을 넘지 않게 했다(오히려 2줄로 줄어 여유가 생겼다).
  - [2026-09-07 수정] 헤더 라벨은 "2026.09.06 ~ 2026.09.19"처럼 **연.월.일 형식의 날짜 범위**로 표기한다(요일·월 단위 텍스트 없이 시작~종료일만). 2주가 월을 걸쳐도 이 형식 그대로라 별도 표기가 필요 없고, 달력 칸에서는 그 달의 1일에만 작게 월 라벨을 붙여 월이 바뀌는 지점만 표시한다.
  - 점 색상 의미(회색=미등록, 노랑/주황=확인 필요, 초록=완료)는 그대로이며, 화면 상단 범례도 유지한다.

## 유의 사항

- 실제 파일 업로드·엑셀 다운로드·데이터 저장은 이 퍼블리싱 단계에서 데모 동작으로만 표현한다.
- 관리자 권한 등급, 계정 초기화의 의미, 휴면 기준, 강제 탈퇴의 데이터 처리 등은 확정 전이다. UI에서 확정 기능처럼 표현하지 않는다.
- 고객의견·계정·사업장 데이터는 예시 값이며, 실제 개인정보를 넣지 않는다.
