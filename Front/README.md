# 해비치 급식 App Front 퍼블리싱 가이드

임직원용 해비치 급식 App의 사용자 화면 퍼블리싱 결과물입니다. 화면 구조, 공통 컴포넌트, 화면 전환과 검토용 상태 UI를 포함합니다.

- 기준 기획서: `SB/해비치 급식 App-0.6.0.html`
- 범위: `PUBLISH/Front` 사용자 화면
- 제외: `PUBLISH/Admin` 관리자 화면
- 현재 작업 기준: 인증 화면 3 + 서비스 화면 2

## 구현안 구분

기존 화면을 보존한 상태에서 서비스 화면 2를 별도 영역으로 구성했습니다. 신규 작업은 서비스 화면 2와 인증 화면 3을 기준으로 합니다.

| 구분 | 대상 | 전용 리소스 |
| --- | --- | --- |
| 서비스 화면 1 | `home.html` 및 Front 루트의 기존 서비스 화면 | `resources/css/style.css`, `resources/js/common.js` |
| 서비스 화면 2 | `service-v2/` | `resources/css/service-v2.css`, `resources/js/service-v2.js` |
| 인증 화면 1·2·3 | `splash*.html`, `login*.html`, `signup*.html`, `password-reset*.html` | `resources/js/auth.js`, 각 인증 전용 CSS |

서비스 화면 2는 기존 `style.css`, `common.js`를 사용하거나 수정하지 않습니다.

## 서비스 화면 2 UI 기준

### 앱 프레임과 하단 탭

`.meal-v2-app`이 뷰포트 높이를 가진 앱 프레임이며, 본문만 내부 스크롤됩니다. 하단 탭은 홈·나의 의견·공지·My에서 프레임 하단에 고정되어 보입니다.

- 탭 노출: 홈, 메뉴 상세, 나의 의견·내역, 공지·공지 상세, My
- 탭 미노출: 비밀번호 변경, 정책, 앱 버전, 회원 탈퇴
- 데스크톱에서는 모바일 앱 프레임에 라운드와 그림자를 적용합니다.

### 식단

- 홈은 조식·중식·석식 카드와 날짜 이동을 제공합니다.
- 조식 미운영과 전체 식단 미등록 상태를 각각 안내합니다.
- 코너는 선택 정보이므로 카드에는 메뉴명을 먼저 표시하고, 코너가 있을 때만 보조 정보로 표시합니다.
- 메뉴 상세는 메뉴명·코너/유형, 메뉴 구성, 원산지·알레르기 정보, 영양소 정보, 의견 쓰기 순서입니다.
- 원산지와 알레르기는 메뉴 단위 등록 정보이며, 값이 없는 항목은 노출하지 않습니다.

### 나의 의견

- 의견 유형, 내용, 글자 수, 사진 첨부, 작성 완료 상태를 제공합니다.
- 사진 첨부 안내: `JPG, PNG · 장당 최대 3MB · 최대 3장 · 총 10MB`
- 형식, 장당 용량, 총 용량, 최대 장수 상태와 삭제 후 재첨부 상태를 화면에 제공합니다.

### 공지와 My

- 공지는 목록·상세, 전체 공지 팝업, 일반 알럿을 각각 제공합니다.
- 전체 공지 팝업과 일반 알럿은 서비스 화면 2의 플로팅 카드 톤으로 구성합니다.
- My에는 프로필 요약, 비밀번호 변경, 이용약관·개인정보처리방침, 앱 버전, 로그아웃, 회원 탈퇴가 있습니다.
- 회원가입의 개인정보 수집 및 이용 동의는 My에 노출하지 않습니다. My의 문서 메뉴는 이용약관과 개인정보처리방침만 다룹니다.

## 인증 화면 3 UI 기준

- 로그인과 회원가입은 하나의 화면 안에서 시트 전환으로 구성합니다.
- 회원가입 추가 정보인 소속 구분, 직급, 성별, 연령대는 모두 필수 선택값입니다.
- 성별 선택값은 여성·남성입니다.
- 개인정보 수집 및 이용 동의 전문은 중앙형 공통 레이어 팝업으로 표시합니다.
- 입력 오류와 필수값 안내는 시트 높이를 바꾸지 않는 공통 토스트로 표시합니다.
- 인증 화면 3의 완료 화면과 서비스 화면 2의 로그아웃은 위의 현재 화면 흐름을 따릅니다.

## 리소스와 유지 원칙

- 서비스 화면 2 HTML은 공통 `resources/`의 `reset.css`, `theme-haevichi.css`, `service-v2.css`, `service-v2.js`만 사용합니다.
- 인증 화면 3은 `reset.css`, `auth-v3.css`, `auth.js`를 사용합니다.
- Pretendard Variable은 `resources/fonts/PretendardVariable.woff2`를 사용합니다.
- 신규 서비스 화면 2 컴포넌트는 `service-v2.css`와 `service-v2.js`에 추가합니다.
- 기존 서비스 화면 1의 구조·스타일·스크립트는 회귀 범위이므로 변경하지 않습니다.

## 정적 퍼블리싱 범위

- 화면의 메뉴·공지·의견·프로필 값은 화면 검토용 예시 데이터입니다.
- URL 파라미터와 `window.location.href` 이동은 화면 흐름 확인용입니다.
- 가입, 로그인, 메일 인증, 파일 업로드, 공지 노출 조건 등 실제 서비스 처리는 개발 연동 대상입니다.
- 이용약관, 개인정보처리방침, 개인정보 수집 및 이용 동의 전문은 운영 확정 문안으로 교체해야 합니다.

## 점검

- HTML 경로와 이미지 경로는 각 화면의 상대 경로 기준으로 유지합니다.
- JavaScript 변경 후에는 `node --check resources/js/auth.js` 또는 `node --check resources/js/service-v2.js`로 문법을 확인합니다.
- 화면 시각 검토는 브라우저에서 서비스 화면 2와 인증 화면 3을 기준으로 진행합니다.

## 기획서 반영용 현재 UI 정책

이 절은 현재 퍼블리싱에 실제로 표현된 사용자 경험을 기록합니다. 기획서 보정 시에는 아래 내용을 화면 정책으로 우선 반영하고, 법무 문안·서버 정책처럼 아직 확정되지 않은 내용은 별도 결정 항목으로 관리합니다.

### 1. 인증 및 회원가입

| 화면/단계 | 사용자에게 보이는 구성 | 현재 UI 기준 |
| --- | --- | --- |
| 로그인 | 사내 메일 주소, 비밀번호, 자동로그인, 비밀번호 찾기, 회원가입 | 입력 오류는 시트 내부 높이를 늘리지 않고 하단 공통 토스트로 안내 |
| 회원가입 1 | 사내 메일 주소, 개인정보 수집 및 이용 동의, 전문 보기 | 이메일 주소 수집·이용 동의는 메일 인증 이전에 받음 |
| 회원가입 2 | 인증번호 6자리, 재발송, 유효시간 안내 | `인증번호는 10분 동안 유효합니다.`를 기본 안내로 표시 |
| 회원가입 3 | 소속 구분, 직급, 성별, 연령대, 개인정보 수집 및 이용 동의, 전문 보기 | 네 선택값과 동의는 모두 필수이며, 성별은 여성·남성 중 하나를 선택 |
| 회원가입 4 | 비밀번호, 비밀번호 확인 | 가입 완료 후 서비스 화면 2 홈으로 이동 |

회원가입은 단일 페이지 안에서 단계별 시트를 전환합니다. 이전 단계로 돌아가기는 각 단계에서 제공하며, 첫 단계에서는 로그인 시트로 돌아갑니다.

#### 추가 정보 선택값

| 항목 | 현재 노출값 | 필수 여부 |
| --- | --- | --- |
| 소속 구분 | 현대캐피탈, 협력사 | 필수 |
| 직급 | 사원, 주임·대리, 과장, 차장, 부장 이상, 임원 | 필수 |
| 성별 | 여성, 남성 | 필수 |
| 연령대 | 20대, 30대, 40대, 50대, 60대 이상 | 필수 |

`응답하지 않음`, `선택 안 함`, 선택 항목 표기는 회원가입 추가 정보 화면에 사용하지 않습니다.

#### 개인정보 수집 및 이용 동의 레이어

동의 전문은 화면 하단 시트가 아닌 화면 중앙의 공통 레이어 팝업으로 표시합니다. 동의 항목은 가입 단계에 따라 달라집니다.

| 동의 시점 | 수집 항목 | 이용 목적 |
| --- | --- | --- |
| 사내 메일 주소 입력 단계 | 사내 이메일 주소 | 로그인 ID 관리, 회원 식별 및 이메일 인증 |
| 추가 정보 입력 단계 | 소속 구분, 직급, 성별, 연령대 | 회원 정보 관리 및 급식 서비스 운영 |

각 레이어에는 수집 항목, 이용 목적, 보유 기간, 동의 거부 시 제한 안내를 표시합니다. 현재 전문은 화면 구조 검토용 문안이므로 법무·해비치 협의 후 최종 문안으로 교체합니다.

#### 인증 공통 안내 방식

- 로그인·회원가입의 필수값, 형식, 불일치, 미허용 도메인 안내는 공통 토스트를 사용합니다.
- 토스트는 하단 버튼 영역 위에 표시하며, 입력 폼의 높이·버튼 위치를 변경하지 않습니다.
- 인라인 오류 영역은 인증 화면 3에서 화면 흐름을 밀지 않도록 사용하지 않습니다.
- 일반 알럿과 개인정보 동의 레이어는 목적이 다르므로 토스트와 혼용하지 않습니다.

### 2. 서비스 화면 2 홈과 식단

#### 홈 구성

```text
브랜드 헤더
오늘의 식사
지난주 / 이번 주 / 다음 주
요일·날짜 선택
공지 배너
조식
중식
석식
하단 탭
```

- 주간 이동을 선택하면 해당 주의 날짜 목록을 다시 표시하고, 기본 선택일은 수요일입니다.
- 날짜를 선택하면 조식·중식·석식 영역을 같은 화면에서 갱신합니다.
- 식단 카드에는 메뉴명, 선택적 코너명, 대표 이미지가 표시됩니다.
- 코너는 운영 상황에 따라 없을 수 있으므로 메뉴명이 항상 먼저 오고 코너명은 있을 때만 보조 정보로 표시합니다.
- 홈 공지 배너는 닫을 수 있으며, 공지 상세로 연결됩니다.

#### 식단 미운영·미등록 상태

| 상태 | 노출 위치 | 안내 문구 |
| --- | --- | --- |
| 특정 식사 미운영 | 해당 조식·중식·석식 영역 | `[식사명] 식단이 등록되지 않았어요` / `다른 식사를 확인해 주세요.` |
| 하루 전체 미등록 | 식단 영역 전체 | `등록된 식단이 없습니다` / `다른 날짜의 식단을 확인해 주세요.` |

현재 예시 상태는 이번 주 9월 3일 조식 미운영, 9월 4일 전체 식단 미등록입니다.

#### 메뉴 상세 정보 위계

```text
대표 이미지
메뉴명
코너 · 유형
메뉴 구성과 항목별 kcal
원산지 · 알레르기 정보
영양소 정보
의견 쓰기
```

- 메뉴 구성은 현재 메뉴 카드에 등록된 항목과 항목별 열량을 표시합니다.
- 원산지와 알레르기는 세부 구성 메뉴별 정보가 아니라 전체 메뉴 등록 정보입니다.
- 원산지·알레르기 정보는 영양소 정보 위의 독립 섹션이며, 한 카드 안에 항목별 블록으로 표시합니다.
- 원산지 또는 알레르기 값이 없으면 해당 항목은 표시하지 않습니다.
- 원산지·알레르기 섹션과 영양소 섹션은 동일한 제목 위계를 사용합니다. 카드 안의 보조 라벨과 값도 영양소 카드의 라벨·수치 위계에 맞춥니다.
- 영양소 정보는 열량, 탄수화물, 단백질, 지방, 나트륨의 한 끼 총합 요약입니다.

### 3. 나의 의견

#### 작성 화면

| 항목 | 현재 UI 기준 |
| --- | --- |
| 의견 유형 | 맛/메뉴, 위생, 서비스, 시설/환경, 앱 사용, 제안, 기타 중 하나 선택 |
| 의견 내용 | 필수, 최대 500자, 실시간 글자 수 표시 |
| 사진 첨부 | 선택, JPG·PNG만 허용, 장당 3MB, 최대 3장, 총 10MB |
| 제출 완료 | 공통 완료 알럿을 표시한 뒤 나의 의견 내역으로 이동 |

사진 첨부 영역은 다음 상태를 모두 제공합니다.

- 정상 추가: 미리보기와 삭제 버튼 표시
- 허용되지 않은 형식: `JPG 또는 PNG 파일만 첨부할 수 있습니다.`
- 장당 용량 초과: `사진은 장당 최대 3MB까지 첨부할 수 있습니다.`
- 총 용량 초과: `사진 총 용량은 최대 10MB까지 첨부할 수 있습니다.`
- 최대 장수 초과: `사진은 최대 3장까지 첨부할 수 있습니다.`
- 삭제 후 재첨부: 첨부 가능 수량이 남으면 사진 추가 버튼을 다시 표시

의견 내용 미입력과 사진 제한 안내는 의견 화면의 말풍선형 검증 UI를 사용합니다.

#### 의견 내역

- 목록은 처리 상태와 작성 정보를 보여 줍니다.
- 첨부 이미지는 이미지 미리보기 레이어에서 확대해 볼 수 있습니다.
- 상세 답변·처리 상태는 화면 구조만 제공하며, 실제 데이터는 운영 연동 대상입니다.

### 4. 공지와 공통 팝업

#### 공지

- 공지 목록은 필독 상태, 제목, 날짜를 표시합니다.
- 공지 상세는 제목·날짜·본문을 하나의 카드 안에서 연속된 읽기 흐름으로 표시합니다.
- 공지 상세는 URL의 `id` 값으로 예시 내용을 구분합니다.
- 홈 최초 진입 전체 공지는 별도 독립 HTML로도 확인할 수 있습니다.

#### 전체 공지 팝업

- 배경 위에 떠 있는 카드로 표시합니다.
- 전체 공지 라벨, 제목, 요약, 공지 자세히 보기, 오늘 하루 보지 않기, 확인 버튼을 제공합니다.
- `공지 자세히 보기` 위·아래에는 별도 구분선을 사용하지 않습니다.

#### 일반 알럿

일반 알럿은 공통 컴포넌트로 다음 두 형식을 제공합니다.

| 형식 | 예시 | 버튼 |
| --- | --- | --- |
| 확인형 | 의견이 접수되었습니다 | 확인 1개 |
| 선택형 | 작성 중인 내용이 있어요 | 계속 작성 / 나가기 |

전체 공지 팝업과 일반 알럿은 모두 서비스 화면 2 앱 프레임 위에 떠 있는 카드 톤을 사용합니다.

식단 카드는 아래 단위로 구성됩니다. 기획서에서는 이 구조를 메뉴 등록 단위로 표현합니다.

| 정보 묶음 | 내용 | 고객 화면 노출 |
| --- | --- | --- |

#### 식단 상세 간격·타이포그래피 기준

- 메뉴 구성 아래의 원산지·알레르기 정보와, 원산지·알레르기 정보 아래의 영양소 정보는 같은 섹션 간격을 유지합니다.
- `원산지 · 알레르기 정보`, `영양소 정보`는 동일한 섹션 제목 크기·굵기를 사용합니다.
- 원산지/알레르기 카드의 라벨은 영양소 카드의 항목명과 같은 보조 위계입니다.
- 원산지/알레르기 카드의 값은 영양소 카드의 수치와 같은 강조 위계입니다.
- 원산지와 알레르기는 한 카드 안에 세로로 배치하고, 항목 사이에 표 형태의 가로 구분선을 사용하지 않습니다.

## 화면별 세부 표현 규칙

이 절은 화면을 새로 그리거나 기획서를 보정할 때 참고하는 상세 기준이다. 공통적인 설명 대신, 각 화면에서 유지해야 할 정보 순서·문구 성격·상태를 기록한다.

### HVM-MO-00 ~ HVM-MO-03 — 인증 화면 3

#### 로그인

- 로그인 시트의 정보 순서는 `사내 메일 주소 → 비밀번호 → 자동로그인 / 비밀번호 찾기 → 로그인 → 회원가입`이다.
- 사내 메일 주소와 비밀번호 입력은 동일한 흰색 입력 필드 톤을 사용한다. 자동로그인 체크박스와 비밀번호 찾기는 같은 한 줄에서 좌우로 배치한다.
- 회원가입은 보조 링크가 아니라 로그인 시트의 하단 문장 안에서 자연스럽게 진입한다. 문구는 `처음 이용하시나요? 회원가입`이다.
- 로그인 실패, 이메일 형식 오류, 필수값 누락은 입력 필드 아래에 별도 영역을 만들지 않는다. 버튼 위치와 시트 높이가 변하지 않도록 하단 토스트로만 안내한다.
- 토스트는 시트 최하단에 겹쳐 보이되, 로그인 버튼이나 회원가입 링크를 밀어 올리지 않는다.
- 로그인 시트는 인증 배경 위에 떠 있는 반투명 카드다. 배경 경계선이나 과도한 테두리는 사용하지 않으며, 텍스트와 입력 필드의 대비를 우선한다.

#### 회원가입 1단계 — 사내 메일 주소

- 제목은 `사내 메일 주소를 입력해주세요`이고, 소속 회사의 사내 메일 주소만 가입할 수 있다는 설명을 함께 표시한다.
- 이메일 입력 아래에 `개인정보 수집 및 이용에 동의합니다. (필수)` 체크박스와 `전문 보기`를 둔다.
- 이 단계의 동의는 이메일 인증 및 로그인 ID 사용을 위한 이메일 수집·이용 동의다.
- `전문 보기`는 이메일 수집 항목과 목적을 가진 공통 중앙 레이어를 연다.
- 이메일 주소 형식, 허용되지 않은 도메인, 동의 미체크 안내는 토스트로 표현한다.
- 다음 버튼은 이메일·동의 조건을 만족한 뒤에만 다음 단계로 진행하는 화면 흐름을 표현한다.

#### 회원가입 2단계 — 메일 인증

- 전 단계에 입력한 이메일 주소를 문장 안에 강조해 `…로 인증번호를 보냈어요.`라고 보여 준다.
- 인증번호 입력과 재발송 버튼은 한 줄로 배치한다. 재발송은 보조 조작이고, 확인 버튼보다 강한 시각 우선순위를 갖지 않는다.
- 입력 아래에는 `인증번호는 10분 동안 유효합니다.`를 상시 안내로 둔다.
- 인증번호 불일치·미입력은 토스트로 안내한다. 이 안내로 인해 인증번호 입력과 확인 버튼 사이의 간격이 변하지 않아야 한다.

#### 회원가입 3단계 — 추가 정보

- 화면 제목은 `추가 정보를 입력해주세요`, 설명은 `서비스 제공을 위해 필요한 정보예요.`로 고정한다. 선택 정보라는 표현을 사용하지 않는다.
- 입력 순서는 다음과 같고, 넓은 화면에서는 두 항목씩 한 줄에 배치한다.

```text
소속 구분     직급
성별          연령대
개인정보 수집 및 이용 동의 / 전문 보기
다음
```

- 소속 구분, 직급, 성별, 연령대는 모두 필수다. 각 필드의 초기값은 `선택해주세요`이며, 성별에는 여성·남성만 둔다.
- 성별 라벨의 `선택` 표시, `선택 안 함`, `응답하지 않음` 선택값은 사용하지 않는다.
- 추가 정보 동의는 이메일 동의와 별개의 동의다. `전문 보기`를 누르면 추가 정보 수집 항목과 서비스 운영 목적을 보여 주는 같은 공통 레이어가 열린다.
- 누락 안내는 필드 밑 인라인 문구가 아닌 공통 토스트로 표현한다. 안내 내용은 소속 구분·성별·연령대·직급·동의가 모두 필요하다는 점을 포함한다.
- 가장 많은 정보를 가진 단계이므로, 이 단계의 콘텐츠 높이를 기준으로 회원가입 시트 전체 높이를 설계한다. 다른 단계에서 하단 버튼이 임의로 위로 이동하거나 큰 여백이 남지 않아야 한다.

#### 회원가입 4단계 — 비밀번호 등록

- 비밀번호와 비밀번호 확인을 순서대로 배치한다.
- 비밀번호 관련 검증 문구도 토스트로 처리해 회원가입 시트의 고정 높이를 유지한다.
- 가입 완료 시 서비스 화면 2 홈으로 연결한다.
- `이전 단계로 돌아가기`는 단계별 시트 하단의 일관된 위치에 둔다. 첫 단계에서는 `로그인으로 돌아가기`로 바뀐다.

#### 개인정보 수집 및 이용 동의 전문 레이어

- 모든 동의 전문은 하나의 공통 레이어 컴포넌트를 재사용한다.
- 레이어는 모바일 화면의 하단 시트가 아니라 화면 중앙에 뜨는 문서형 패널이다.
- 헤더에는 제목과 닫기 버튼, 본문에는 안내 문장·수집 항목·이용 목적·보유 기간·거부 시 제한 안내, 하단에는 확인 버튼을 둔다.
- 가입 단계에 따라 본문 데이터만 바뀌며, 레이어의 레이아웃·닫기·확인 패턴은 동일하다.
- My의 이용약관·개인정보처리방침과 회원가입 동의 전문은 목적이 다르므로 동일 메뉴로 합치지 않는다.

### HVM-MO-04 / HVM-MO-04-01 — 홈과 식단 없음

#### 홈 기본 화면

- 상단에는 브랜드만 간결하게 두고, 홈의 첫 제목은 `오늘의 식사`다.
- 주간 이동은 `지난주 / 이번 주 / 다음 주` 3개 선택지로 제공하고, 활성 주는 브랜드 컬러로 구분한다.
- 날짜는 일요일부터 토요일까지 한 줄로 표시한다. 요일은 보조 텍스트, 날짜 숫자는 주 정보이며 선택 날짜는 강조 배경으로 표시한다.
- 홈 공지 배너는 날짜 선택 다음에 배치한다. 공지 전체를 가리지 않고 한 줄 제목과 닫기 조작을 제공하며, 제목을 누르면 공지 상세로 이동한다.
- 조식·중식·석식은 시간과 함께 각각 독립 섹션으로 표시한다. 한 끼 안에 여러 메뉴가 있으면 카드 그리드로 보여 준다.
- 메뉴 사진 카드에는 메뉴명이 첫 줄, 코너명이 두 번째 보조 줄이다. 코너를 운영하지 않는 메뉴는 코너 줄을 비워서 메뉴명만 보여 준다.
- 하단 탭은 홈에서 항상 활성 상태의 홈 아이콘과 라벨을 표시한다.

#### 식단 없음 상태

- 특정 끼니가 없을 때는 조식·중식·석식 섹션 자체를 제거하지 않는다. 기존 식사 제목과 시간 아래에 빈 상태 카드를 표시한다.
- 특정 끼니의 제목은 `[식사명] 식단이 등록되지 않았어요`, 보조 문구는 `다른 식사를 확인해 주세요.`다.
- 하루 전체 식단이 없을 때는 조·중·석 빈 카드를 반복하지 않는다. 식단 콘텐츠 전체에 하나의 빈 상태 카드만 표시한다.
- 전체 빈 상태 제목은 `등록된 식단이 없습니다`, 보조 문구는 `다른 날짜의 식단을 확인해 주세요.`다.
- 두 상태 모두 단순 텍스트만 쓰지 않고, 서비스 화면 2의 부유하는 카드 톤과 식단 빈 상태 일러스트를 사용한다.

### HVM-MO-06 — 메뉴 상세

#### 상단과 메뉴 구성

- 상단 헤더에는 뒤로가기와 `메뉴 상세` 제목을 둔다.
- 대표 이미지는 상세 콘텐츠의 첫 영역이며, 이미지 아래에 메뉴명과 `코너 · 유형` 보조 정보를 둔다.
- 메뉴명 옆이나 위에 원산지·알레르기·영양소를 섞지 않는다. 메뉴 구성 목록은 메뉴명과 한 묶음으로 유지한다.
- 메뉴 구성 목록은 `항목명` 왼쪽, `kcal` 오른쪽의 가벼운 목록으로 표시한다. 개별 항목을 카드나 표로 과도하게 분리하지 않는다.

#### 원산지·알레르기 정보

- 메뉴 구성 다음, 영양소 정보 이전에 `원산지 · 알레르기 정보` 섹션을 둔다.
- 이 섹션의 제목 크기와 굵기는 `영양소 정보`와 동일하다. 메뉴명보다 낮고, 카드 내부의 보조 정보보다 높다.
- 원산지와 알레르기는 하나의 흰 카드 안에 세로로 놓는다. 각 항목은 `보조 라벨 → 강조값` 구조다.
- 원산지/알레르기 라벨은 영양소의 `열량`, `탄수화물` 라벨과 같은 위계다. 값은 `890kcal`, `210g` 같은 영양소 수치와 같은 강조 위계다.
- 원산지와 알레르기 항목 사이에 테이블식 가로선·세로선을 사용하지 않는다. 여백만으로 항목을 구분한다.
- 원산지 정보가 길어질 수 있으므로 두 항목을 고정 폭의 좌우 열로 나누지 않는다.
- 원산지 또는 알레르기 데이터가 없을 수 있으므로, 값이 없는 항목은 빈 영역을 남기지 않고 숨긴다. 한 항목만 있어도 카드 구조는 유지한다.

#### 영양소와 의견 쓰기

- 영양소 정보는 원산지·알레르기 정보와 같은 섹션 간격을 유지한다.
- 영양소 카드는 열량, 탄수화물, 단백질, 지방, 나트륨을 같은 폭의 요약값으로 보여 준다.
- `의견 쓰기` 버튼은 상세 콘텐츠의 마지막 주요 행동이다. 현재 메뉴·코너 맥락을 유지한 채 의견 작성 화면으로 연결한다.

### HVM-MO-07 / HVM-MO-08 — 의견 작성과 내역

#### 의견 작성

- 페이지 제목은 의견의 성격을 바로 알 수 있도록 `나의 의견` 흐름 안에서 표시한다.
- 유형 선택은 라디오·드롭다운보다 빠르게 고를 수 있는 버튼 칩 묶음이다. 기본 선택은 `맛/메뉴`다.
- 칩 노출값은 `맛/메뉴`, `위생`, `서비스`, `시설/환경`, `앱 사용`, `제안`, `기타`다.
- 본문 제목은 `의견을 들려주세요`, 필수 표기를 함께 둔다. 입력 가능 글자 수는 최대 500자이고, 오른쪽에 현재 글자 수를 표시한다.
- 본문이 비어 있는 상태에서 제출하면 입력 영역 아래에 말풍선형 안내 `이 입력란을 작성하세요.`를 표시한다.
- 사진 섹션 제목은 `사진을 함께 보낼까요?`, 보조 문구는 `선택 · 최대 3장`이다.
- 제한 문구는 사진 영역 바로 아래에 `JPG, PNG · 장당 최대 3MB · 최대 3장 · 총 10MB`로 항상 표시한다.
- 사진이 추가되면 미리보기와 삭제 버튼을 표시하고, 3장 미만이면 사진 추가 버튼을 유지한다. 3장이 되면 최대 첨부 상태를 표현한다.
- 형식·용량·장수 오류는 본문 오류와 동일한 말풍선형 UI를 사진 영역 아래에 사용한다.
- 작성 완료 알럿은 성공 메시지와 확인 버튼을 제공하고, 확인 후 의견 내역으로 이동한다.

#### 의견 내역

- 목록에서는 작성일, 유형, 처리 상태, 본문 요약을 빠르게 확인할 수 있어야 한다.
- 첨부 이미지가 있는 항목은 미리보기 진입을 제공한다. 이미지는 오버레이 레이어에서 크게 확인하고, 닫기 버튼·배경 클릭·Esc 키로 닫을 수 있다.
- 목록과 상세/답변은 하나의 화면에서 과도하게 확장하지 않고, 필요한 정보만 단계적으로 보여 준다.

### HVM-MO-09 — 공지

#### 공지 목록과 상세

- 공지 목록은 필독 여부, 제목, 날짜를 우선한다. 카드 자체는 가볍게 보이고, 정보가 여러 박스로 분절되지 않는다.
- 공지 상세는 제목과 본문을 별도 카드로 나누지 않는다. 하나의 읽기 카드 안에서 필독 라벨(해당 시) → 제목 → 날짜 → 본문 순서로 이어진다.
- 상세 본문은 줄바꿈을 유지하고, 읽기 폭과 행간을 확보한다.
- 공지와 공지 상세 모두 하단 탭을 유지해 주요 화면 사이 이동 흐름을 끊지 않는다.

#### 전체 공지 팝업과 일반 알럿

- 전체 공지 팝업은 홈 위에 떠 있는 큰 카드이며, 전체 공지 라벨·제목·요약·자세히 보기·오늘 하루 보지 않기·확인 순서다.
- `공지 자세히 보기`는 링크처럼 보이되 위·아래에 선을 추가하지 않는다.
- 일반 알럿은 완료 확인형과 선택형 두 종류다. 완료 확인형은 아이콘·제목·설명·확인으로 구성하고, 선택형은 제목·설명·보조 버튼·주요 버튼으로 구성한다.
- 팝업과 알럿은 배경 위에 떠 있어야 하며, 일반 콘텐츠 카드처럼 본문 흐름에 붙어 있으면 안 된다.

### HVM-MO-10 ~ HVM-MO-13 — My와 정책 화면

#### My 메인

- 프로필 영역은 이메일을 주 정보, 소속을 보조 정보로 표시한다.
- 메뉴는 계정 관리 영역(비밀번호 변경, 약관·개인정보처리방침, 앱 버전)과 위험 행동 영역(로그아웃, 회원 탈퇴)을 시각적으로 분리한다.
- 로그아웃은 서비스 화면 2에서 인증 화면 3으로 돌아가는 흐름이다.
- My는 가입 단계에서 받은 모든 추가 정보를 수정하는 화면이 아니다. 성별·연령대·직급 수정 UI는 현재 포함하지 않는다.

#### 비밀번호 변경

- 현재 비밀번호 확인과 새 비밀번호 등록은 한 화면에서 동시에 노출하지 않고 2단계로 분리한다.
- 각 단계의 이전 이동은 현재 입력 흐름을 해치지 않는 보조 버튼으로 둔다.
- 완료, 실패, 세션 처리와 같은 서비스 동작은 화면 문구·알럿 구조만 준비하며, 화면 외 정책은 이 문서에서 확정하지 않는다.

#### 이용약관·개인정보처리방침·앱 버전·탈퇴

- My의 문서 메뉴는 이용약관과 개인정보처리방침이다. 회원가입용 개인정보 수집 및 이용 동의 전문은 포함하지 않는다.
- 개인정보처리방침은 버전을 선택해 본문을 바꾸는 화면 구성을 제공한다.
- 앱 버전은 앱 버전과 오픈소스 라이선스를 읽는 정보 화면이다.
- 회원 탈퇴는 비밀번호, 탈퇴 사유, 최종 안내 확인·동의를 차례로 받는 화면이다. 탈퇴 사유에서 기타를 선택한 경우에만 추가 입력란을 보여 준다.

## 공통 컴포넌트 정책

### 하단 탭

- 항목은 홈, 나의 의견, 공지, My로 고정합니다.
- 선택된 탭은 브랜드 컬러와 활성 아이콘으로 표시합니다.
- 화면 본문은 탭 위에서만 스크롤되고, 탭은 항상 앱 프레임 하단에 남아 있습니다.
- 상세 화면도 서비스 탐색 흐름을 유지해야 하는 메뉴 상세·공지 상세·의견 작성/내역에는 탭을 표시합니다.
- 계정 설정과 문서 읽기처럼 완료 후 돌아오는 흐름의 My 하위 화면에는 탭을 표시하지 않습니다.

### 토스트, 알럿, 레이어의 구분

| 컴포넌트 | 쓰는 상황 | 위치/형태 | 예시 |
| --- | --- | --- | --- |
| 인증 토스트 | 로그인·회원가입의 필수값 및 형식 안내 | 인증 시트 하단 버튼 위 | 이메일 형식, 동의 필요, 인증번호 불일치 |
| 의견 검증 말풍선 | 의견 본문·사진 첨부 제한 | 해당 입력 영역 아래 | 입력란 작성, JPG/PNG 제한, 용량 초과 |
| 일반 알럿 | 완료 확인 또는 사용자 선택 필요 | 서비스 화면 중앙 플로팅 카드 | 의견 접수 완료, 작성 중 내용 이탈 확인 |
| 개인정보 동의 레이어 | 전문 열람 | 화면 중앙 레이어 | 수집 항목·이용 목적·보유 기간 |
| 전체 공지 팝업 | 서비스 공지 고지 | 서비스 화면 중앙 플로팅 카드 | 서비스 시작 안내 |

같은 오류라도 화면 성격에 맞는 컴포넌트를 사용합니다. 예를 들어 인증의 형식 오류를 입력 영역 아래에 추가하거나, 의견 사진 제한을 전역 토스트로 바꾸지 않습니다.

## 소스 기준 변경 위치

| 변경 대상 | 기준 파일 | 함께 확인할 화면 |
| --- | --- | --- |
| 인증 화면 3 구조·문구 | `splash-v3.html` | `resources/js/auth.js`, `resources/css/auth-v3.css` |
| 인증 단계·동의·토스트 | `resources/js/auth.js` | `splash-v3.html` |
| 서비스 화면 2 공통 톤·프레임·카드 | `resources/css/service-v2.css` | `service-v2/` 전체 |
| 식단·My·의견·공지 상태 | `resources/js/service-v2.js` | `service-v2/meal`, `voc`, `notice`, `my` |
| 서비스 화면 2 개별 마크업 | `service-v2/**.html` | 해당 화면 전용 |

서비스 화면 2를 수정할 때 기존 서비스 화면 1 파일이나 `resources/js/common.js`를 임의로 함께 바꾸지 않습니다. 반대로 서비스 화면 1의 문서 보정이 필요하면 서비스 화면 2와 분리해 다룹니다.

## 기획 확정 전 문안 관리

다음은 현재 화면에 구조와 예시 문구가 있으나, 최종 운영 문안이 확정되면 교체해야 하는 항목입니다.

- 개인정보 수집 및 이용 동의 전문과 보유 기간
- 이용약관·개인정보처리방침의 최종 문안, 버전, 시행일
- 공지의 실제 제목, 본문, 노출 기간, 오늘 하루 미노출 기준
- My 프로필의 실제 소속 표기 방식
- 앱 버전과 오픈소스 라이선스 정보
