### 2-2. CSS 파일 구조 정리 (화면 변화 없음)

**완료 결과.** `style.css`를 제거하고, 공통 기반은 `base.css`, 서비스·인증 화면 전용 규칙은 각각
`service.css`·`auth.css`로 분리했다. 모든 HTML은 `base.css?v=20260917-3`를 로드하며,
서비스 화면은 `reset → base → theme → service`, 인증 화면은 `reset → base → auth` 순서다.
개발 가이드 2·3·9장과 타이포 가이드 6장도 같은 구조와 확정 상태로 갱신했다.

**현재 문제.** 같은 요소의 폰트·색이 `style.css`와 `service.css` 두 곳에 따로 선언돼 있다.
`service.css`가 뒤에 로드돼 이기지만, `style.css`에는 죽은 옛값이 그대로 남아 있다.

```css
style.css:535     .detail-name{ font-size:23px; font-weight:800; }        /* 죽은 값 */
service.css:327   .detail-name{ font-size:var(--fs-hero); font-weight:600; }  /* 실제 20px */
```

이런 중복이 90군데 가량이다. 개발이 `style.css`만 열면 **틀린 값을 본다.**

**왜 이렇게 됐나.** `style.css`를 고치면 다른 퍼블리싱 안이 깨진다고 보고 덧칠만 했다.
그러나 `service-v3/`는 `resources/`를 자체 사본으로 갖고 있어 **그 전제가 성립하지 않는다.**
이 판단 착오로 개발 가이드 3장에도 *"`style.css`는 수정하지 않습니다"*라는
**잘못된 원칙이 적혀 있다. 함께 걷어내야 한다.**

**현재 구성과 규칙 분류** (`style.css` 352개 규칙 기준)

```
reset.css        17줄   브라우저 리셋
style.css       668줄   서비스·인증 공용 기반      ← 서비스 전용 215 / 인증 전용 57 / 공통 32 / 사문 48
theme-*.css      23줄   회사 색 (분리 유지 필수)
service.css     407줄   서비스 화면 덧칠 + 토큰
auth.css        111줄   인증 화면 덧칠 + 토큰
```

**목표 구성**

```
reset.css        브라우저 리셋 (그대로)
base.css         공통 토큰 + 공통 32개 규칙          ← 신규
theme-*.css      회사 색 (그대로)
service.css      서비스 화면 전용, 최종값 하나만       ← style 215 + service 병합
auth.css         인증 화면 전용, 최종값 하나만        ← style 57 + auth 병합
                 사문 48개 삭제
```

**단순 병합은 안 된다.** `style.css`를 인증 화면도 쓰기 때문에, 서비스 전용 값을
그대로 합치면 인증 화면으로 새어 들어간다. 위 분류대로 나눈 뒤 병합해야 한다.

**완료 기준: 화면이 한 픽셀도 바뀌지 않아야 한다.**
전 화면 × 전 요소의 최종 계산값을 작업 전후로 뽑아 대조하고, 차이가 0인지 확인한다.

## 3. 반드시 지킬 제약

작업하다 되돌리기 쉬운 것들이다. 각각 그렇게 된 이유가 있다.

| 제약 | 이유 |
| --- | --- |
| **탭바 아이콘은 data URI 마스크를 유지한다** | CSS `mask`는 동일 출처 제한을 받는다. 외부 `.svg`로 되돌리면 `file://`로 HTML을 직접 열 때 아이콘이 통째로 사라진다. 로컬 서버에서는 보이므로 눈치채기 어렵다 |
| **`theme-oncolor.js`는 `<head>`에서 동기 로드한다** | 본문 스크립트로 옮기면 첫 페인트 이후 글자색이 바뀌어 화면이 튄다 |
| **`@font-face`는 `service.css`·`auth.css` 양쪽에 있어야 한다** | 인증 화면은 `service.css`를 로드하지 않는다. 한쪽만 두면 인증 화면이 시스템 폰트로 렌더된다. 새 CSS 파일을 만들 때도 같다 |
| **굵기는 400/600 두 단계만 쓴다** | `.meal-tab.is-active`·`.voc-tab.is-active`의 선택 상태 600이 유일한 예외다 |
| **`theme-*.css`는 분리를 유지한다** | 회사가 늘어날 때 이 파일 하나만 추가하는 구조다 |
| **캐시 버전은 전 파일 동일하게 올린다** | HTML에는 버전이 없으므로, 확인 시 강제 새로고침이 필요하다는 점도 함께 안내할 것 |
| **메뉴 이미지는 원본 비율 유지** | 고정 비율 크롭을 넣지 않는다. 확정 사항이다 |

## 4. 검증 방법

이 폴더에서 아래를 돌린다. 개발 가이드 11장의 점검 결과도 이 기준으로 갱신한다.

```bash
# 자산 경로 실재 / 중복 id / JS 참조 id / 없는 화면 참조 / 테마 화면 스크립트 연결
# (개발 가이드 11장 항목과 동일)
node --check resources/js/common.js
node --check resources/js/auth.js
node --check resources/js/theme-oncolor.js
```

CSS 정리 시에는 **최종 계산값 대조**가 핵심이다. 선택자별로
`style.css → theme → service.css`(서비스) / `style.css → auth.css`(인증) 순서로
마지막 선언을 취해 before/after를 비교하면 된다.

**화면 확인은 사용자가 직접 한다.** 브라우저를 열어 스크린샷으로 자체 검증하지 않는다.
무엇을 봐야 하는지만 짧게 안내한다.
