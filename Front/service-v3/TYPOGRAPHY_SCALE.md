## 1. PDF 수치를 그대로 반영하지 않은 이유

PDF의 레벨 구분과 위계는 그대로 따랐습니다. 다만 **각 레벨의 절대 크기만** 한 단계 올렸습니다.

### 1) 모바일 본문 하한 아래입니다

PDF 기준의 Body는 11~12px, Caption은 10px입니다. iOS 기본 본문이 17pt, Material 권장 최소가 14sp인 것을 감안하면 이 값들은 **읽는 정보가 아니라 보조 중의 보조** 구간에 해당합니다. 메뉴 구성, 공지 제목, 영양 정보처럼 실제로 읽어야 하는 항목에 쓰기에는 작습니다.

### 2) 한글은 같은 px에서 한 단계 불리합니다

한글은 음절 블록 안에 획이 몰려 있어, 같은 크기의 라틴 문자보다 작고 뭉개져 보입니다. 라틴 기준으로 설계된 스케일을 한글에 그대로 옮기면 체감상 한 단계 손해를 봅니다.

### 3) 사용자층과 사용 맥락

사내 급식 App은 전 연령 임직원이 사용하며 식당 앞에서 서서 몇 초 안에 훑어보는 화면입니다. 앉아서 들여다보는 화면과 다른 기준이 필요합니다.

> PDF에 함께 표기된 `Page Padding 20px`는 실제 모바일 표준 여백값입니다. 같은 좌표계 기준으로 읽으면 폰트 수치도 실제 CSS px를 의도하신 것으로 이해했습니다. 이 해석이 다르다면 알려주시기 바랍니다.

## 2. 적용 정책 및 제외 항목

### 2-1. 레벨별 크기 매핑

| 레벨 | PDF 기준 | 적용 | 용도 |
| --- | --- | --- | --- |
| Caption | 10 / 400 | **12 / 400** | 메타 정보, 배지, 보조 표기 |
| Body | 11 / 400 | **13 / 400** | 보조 본문, 탭 |
| Body | 12 / 400 | **14 / 400** | 본문, 입력값 |
| Card Title | 12 / 600 | **14 / 600** | 카드 제목, 입력 라벨 |
| Button | 12 / 600 | **14 / 600** | 버튼 |
| Section | 13 / 600 | **15 / 600** | 섹션 제목 |
| Main | 15 / 600 | **17 / 600** | 화면 제목 |
| Hero | (Main 15 / 600) | **20 / 600** | 상세 화면 대표 제목 — 5-1 참고 |
| Display | 20 / 600 | **22 / 600** | 스플래시 브랜드 메시지 |

### 2-2. 굵기 정책

PDF와 동일하게 **400 / 600 두 단계만** 사용합니다.

- 기존 퍼블리싱 소스에 있던 500 / 700 / 800 / 900은 전부 정리했습니다.
- 반 px(11.5 / 12.5 / 13.5)도 함께 제거했습니다.
- 예외는 5-2의 탭 선택 상태 한 건이며, 이 경우에도 400 / 600 범위 안에서 처리했습니다.

### 2-3. 서비스 화면과 인증 화면은 같은 체계입니다

로그인·회원가입·비밀번호 재설정과 로그인 이후 서비스 화면이 **하나의 타이포 스케일**을 공유합니다. 로그인에서 홈으로 넘어갈 때 본문 크기가 달라지지 않습니다.

### 2-4. 스케일 적용 대상이 아닌 항목

아래 항목은 글자이지만 아이콘·구조 요소로 쓰이므로, 타이포 스케일과 별개로 관리합니다.

| 항목 | 값 | 사유 |
| --- | --- | --- |
| 목록 화살표 `›` | 22px | 아이콘 문자. 행 높이에 맞춘 값 |
| 사진 추가 `＋` | 25px | 아이콘 문자 |
| 닫기 `×` | 19~25px | 아이콘 문자 |
| 알럿 심볼 `✓` | 24px | 44px 원 안의 심볼 |
| 회원가입 단계 원 | 지름 22px | 숫자 12px를 담기 위해 20 → 22px로 조정 |

## 5. PDF와 다르게 판단한 항목

크기 일괄 +2 외에, 아래 세 가지는 PDF 기준과 다르게 적용했습니다. **협의가 필요한 항목입니다.**

### 5-1. 상세 화면 대표 제목 — Hero 레벨 신설

식단 상세와 공지 상세에는 **별도의 화면 제목이 없습니다.** 상단 바에 날짜나 뒤로가기만 있고, 콘텐츠 제목(메뉴명 / 공지 제목)이 그 자리를 대신합니다.

PDF는 이 항목도 `Main 15/600`으로 매기셨는데, 스케일을 그대로 적용하면 17px가 되어 본문 14px 대비 **1.21배**밖에 차이가 나지 않습니다. 대표 제목이 본문에 붙어 위계가 서지 않습니다.

```
코너 A · 한식   12 / 400
된장국 정식     17 / 600   <- 본문과 3px 차이
잡곡밥          14 / 400
```

그래서 상세 화면의 대표 제목만 **Hero 20 / 600**으로 두었습니다. 본문 대비 1.43배입니다.

| 화면 | 대상 | 적용 |
| --- | --- | --- |
| 식단 상세 | 대표 메뉴명 | 20 / 600 |
| 공지 상세 | 공지 제목 | 20 / 600 |

화면 제목이 따로 있는 화면(홈 · 나의 의견 · 공지 목록 · My)에는 Hero를 쓰지 않습니다. 그 화면들의 최상위는 Main 17 / 600입니다.

### 5-2. 탭 선택 상태의 굵기

PDF는 탭의 선택 상태를 **색으로만** 구분하십니다(대표색 배경 + 흰 글자). 그대로 따르면 선택·비선택이 모두 400인데, 실제 화면에서 선택감이 약해 **선택 시 굵기 한 단계(600)를 함께** 적용했습니다.

| 대상 | 비선택 | 선택 |
| --- | --- | --- |
| 조식 · 중식 · 석식 탭 | 13 / 400 | **13 / 600** |
| 접수 · 내역 탭 | 13 / 400 | **13 / 600** |
| 지난주 · 이번주 · 다음주 | 12 / 400 | 12 / 400 (변경 없음) |

크기는 선택·비선택을 같게 두었습니다. 선택될 때마다 탭 폭이 흔들리는 것을 막기 위함입니다.

주간 이동(지난주 · 이번주 · 다음주)은 대상에서 제외했습니다. 선택 상태를 흰 배경과 그림자로 구분하는 별도 컨트롤이라 탭과 규칙이 다릅니다.

### 5-3. 개인정보 동의 문구

기존 소스에는 좁은 화면에서 줄이 넘칠 때 **폰트를 되레 줄이는 처리**가 있었습니다.

```css
/* 삭제 */
@media (max-width:380px){ .signup-consent{ font-size:9.5px; } }
```

10px 기준에서도 이미 한 줄에 들어가지 않는다는 뜻이므로, 12px로 올리면서 이 처리를 없애고 **두 줄을 전제로 재배치**했습니다. 체크박스를 첫 줄 높이에 맞추고(`align-items:flex-start`), 문구 영역이 남은 폭을 모두 쓰도록 했습니다.

## 6. 개발 참고

### 6-1. 구현 위치와 로드 순서

CSS는 **뒤에 오는 파일이 앞을 덮는 구조**입니다. 반드시 아래 순서를 지켜야 합니다.

```html
<link rel="stylesheet" href="resources/css/reset.css">
<link rel="stylesheet" href="resources/css/style.css">
<link rel="stylesheet" href="resources/css/theme-haevichi.css" id="themeLink">  <!-- 서비스 화면만 -->
<link rel="stylesheet" href="resources/css/service.css">                        <!-- 서비스 화면 -->
<link rel="stylesheet" href="resources/css/auth.css">                           <!-- 인증 화면 -->
<script src="resources/js/theme-oncolor.js"></script>                           <!-- 서비스 화면, head 동기 -->
```

| 파일 | 역할 | 타이포 정의 |
| --- | --- | --- |
| `reset.css` | 브라우저 기본값 초기화 | 없음 |
| `style.css` | 초기 퍼블리싱 구조·레이아웃 | **수정 대상 아님** (6-2 참고) |
| `theme-haevichi.css` | 회사 대표색 `--brand-primary` 한 값 | 없음 |
| `service.css` | 서비스 화면 디자인 시스템 + 타이포 스케일 | **있음** — 하단 전용 섹션 |
| `auth.css` | 인증 화면 전용 디자인 | **있음** |
| `theme-oncolor.js` | 대표색 위 글자색 결정. 타이포 크기·굵기와는 무관 | 없음 |

인증 화면은 회사 확정 전 화면이므로 `theme-*.css`를 연결하지 않습니다.

### 6-2. `style.css`를 수정하지 않는 이유

타이포 값을 `style.css`에서 직접 고치지 않고, `service.css` 하단의 전용 섹션에서 **같은 선택자로 덮어쓰고** 있습니다.

- 초기 퍼블리싱본(Front 루트 · `service-v2/`)이 `style.css`를 공유하므로, 직접 수정하면 이전 안이 함께 깨집니다.
- 타이포 관련 선언이 한 파일 한 섹션에 모여 있어 변경 이력을 추적하기 쉽습니다.

덮어쓰기는 **특이도를 맞추고 로드 순서로만** 이깁니다. `style.css`가 `.corner-list--grid2 .corner-desc`처럼 클래스 2개를 쓰는 곳은, `service.css`도 같은 형태로 선언합니다.

```css
/* style.css */
.corner-list--grid2 .corner-desc{ font-size:11.5px; }

/* service.css — 같은 특이도, 뒤에 오므로 이김 */
.corner-desc,.corner-list--grid2 .corner-desc{ font-size:var(--fs-body-sm); font-weight:400; }
```

> 타이포 값을 바꿀 때는 `style.css`가 아니라 **`service.css` 하단 섹션 / `auth.css`**를 수정하십시오.

### 6-3. 크기 토큰

`service.css`의 `:root`에 선언되어 있습니다. 개별 화면에서 px를 직접 쓰지 않고 토큰을 참조합니다.

```css
:root{
  --fs-display:22px;   /* 스플래시 브랜드 메시지 */
  --fs-hero:20px;      /* 상세 화면 대표 제목 — 그 화면에 화면 제목이 없는 경우에만 */
  --fs-title:17px;     /* 화면 제목, 팝업 제목 */
  --fs-section:15px;   /* 섹션 제목 */
  --fs-label:14px;     /* 카드 제목, 입력 라벨, 버튼, 본문 강조 */
  --fs-body:14px;      /* 본문, 입력값 */
  --fs-body-sm:13px;   /* 보조 본문, 탭 */
  --fs-caption:12px;   /* 캡션, 배지, 메타 */
}
```

`--fs-label`과 `--fs-body`는 현재 같은 14px이지만, 역할이 다르므로 이름을 분리해 두었습니다. 한쪽만 조정해야 할 때 토큰만 바꾸면 됩니다.

### 6-4. HTML 태그와 클래스 규칙

**제목 태그**

| 태그 | 사용처 | 레벨 |
| --- | --- | --- |
| `h1` | 화면 제목, 상세 대표 제목 | Main 17 / Hero 20 |
| `h2` | 약관 조항 제목, 알럿·레이어 제목 | Section 15 / Main 17 |
| `legend` · `label` | 입력 블록 제목, 입력 라벨 | Section 15 / Card Title 14 |

**화면마다 `h1`은 하나만 노출합니다.** 식단 상세·공지 상세는 콘텐츠 제목이 `h1`입니다(5-1).

회원가입과 비밀번호 재설정은 단계마다 `h1`을 두지만(각각 4개 · 3개), 활성 단계를 제외한 나머지 `section`에
`hidden`이 걸려 있어 **한 번에 하나만 노출**됩니다. `hidden` 요소는 접근성 트리에서도 제외되므로,
어느 시점에도 화면에 드러나는 `h1`은 하나입니다. 단계 전환형 폼의 일반적인 구조입니다.

```html
<section class="signup-step" data-signup-step="1">        <h1>메일 주소를 입력해주세요.</h1> …
<section class="signup-step" data-signup-step="2" hidden> <h1>메일을 인증해주세요.</h1> …
```

**상태 클래스**

| 클래스 | 의미 | 사용처 |
| --- | --- | --- |
| `.is-active` | 탭·버튼의 선택 상태, 하단 네비게이션의 현재 화면 | `.meal-tab` · `.voc-tab` · `.week-navigation-button` · `.tabbar a` · `.signup-progress span` |
| `.is-selected` | 날짜 선택 상태 | `.week-day` |
| `.is-complete` · `.is-waiting` | 의견 답변 상태 | `.voc-status` |
| `.is-error` | 입력 오류 문구 | `.form-message` |

선택 상태에서 굵기가 바뀌는 것은 `.meal-tab.is-active` · `.voc-tab.is-active` **두 곳뿐**입니다(5-2).

**폰트**

PDF 공통 기준의 `Font: Pretendard`에 따라 Pretendard Variable 한 종만 사용합니다.
`font-weight:45 920` 범위를 지원하는 가변 폰트이므로 400 / 600에 별도 파일이 필요 없습니다.

```css
/* service.css */
@font-face{
  font-family:"Pretendard";
  src:url("../fonts/PretendardVariable.woff2") format("woff2");
  font-weight:45 920;
}
```

인증 화면은 `service.css`를 로드하지 않으므로, **`auth.css`에도 같은 `@font-face`와 `--font`를 선언**해
두 화면군이 동일한 폰트를 쓰도록 했습니다. `style.css`의 `--font`는 Pretendard가 없는 시스템 폰트 스택이라,
`service.css` · `auth.css`에서 각각 덮습니다.

| 화면군 | 로드하는 CSS | `@font-face` 선언 위치 |
| --- | --- | --- |
| 서비스 | `reset` → `style` → `theme` → `service` | `service.css` |
| 인증 | `reset` → `style` → `auth` | `auth.css` |

> CSS 파일을 새로 추가할 때, 그 파일만 로드하는 화면이 생긴다면 `@font-face`와 `--font`를 함께 선언해야 합니다.

### 6-5. 회사 테마와 타이포는 독립입니다

회사별로 바뀌는 값은 `theme-{company-code}.css`의 **색상 값뿐**입니다. 타이포 스케일은 여기에 영향을 받지 않습니다.

```css
/* resources/css/theme-{company-code}.css */
:root {
  --brand-primary: <회사 대표색>;
  --brand-on-primary: <대표색 위 글자색>;   /* 비우면 대표색 밝기로 자동 판정 */
}
```

현대캐피탈 등 다른 고객사를 추가해도 **타이포 관련 CSS는 수정하지 않습니다.**

### 6-6. 변경 시 확인할 것

- 크기를 바꿀 때는 개별 선언이 아니라 `:root`의 토큰을 수정합니다.
- 새 항목을 추가할 때는 2-1의 레벨 중 하나를 골라 토큰을 참조합니다. 새 px 값을 만들지 않습니다.
- 굵기는 400 / 600 외의 값을 쓰지 않습니다.
- `style.css`에 남아 있는 이전 값(반 px, 700~900)은 `service.css` · `auth.css`가 덮고 있으므로, 브라우저 개발자도구의 **최종 계산값(Computed)** 기준으로 확인하십시오.
