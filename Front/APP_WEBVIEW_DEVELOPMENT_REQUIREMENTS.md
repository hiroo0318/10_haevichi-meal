# 해비치 급식 서비스 앱 개발 요청 사항

작성일: 2026-09-21  
수신: 앱 개발팀

## 1. 요청 목적

해비치 급식 서비스의 모바일 웹을 Android와 iOS 앱으로 제공합니다. 앱은 기존 운영 웹을 WebView로 호출하는
경량 셸 역할이며, 로그인·식단·VOC·공지·My·테마·화면 이동은 웹 서비스가 처리합니다.

## 2. 요청 범위

- Android와 iOS에서 기존 운영 웹을 WebView로 호출합니다.
- 앱의 별도 로그인·회원가입, 앱 네이티브 토큰 관리, 앱↔웹 JavaScript 브릿지는 구현하지 않습니다.

## 3. WebView 기본 구성

- HTTPS 운영 URL을 단일 WebView로 호출합니다.
- 사업장 로고·대표색 등 테마는 웹 서버가 처리하며 앱은 관여하지 않습니다.
- 현재 서비스 범위에는 외부 브라우저로 이동하는 화면이 없습니다.

## 4. 개발 요청 항목

### 4-1. WebView 및 자동로그인 유지

웹 서비스의 인증 방식을 WebView에서 그대로 사용하도록 구현 부탁드립니다.

- Android WebView는 JavaScript와 DOM Storage(`localStorage`)를 활성화합니다. 웹 화면 동작 및 공지의 ‘오늘 하루 보지 않기’ 저장에 필요합니다.
- iOS WebView도 웹의 JavaScript 실행과 영속 웹 데이터 저장소를 기본으로 사용합니다.

| 구분 | 웹 서비스 구성 | 앱 요청 사항 |
| --- | --- | --- |
| 서버 세션 | `JSESSIONID`, 미사용 30분 만료 | WebView가 동일 호스트의 HTTPS 쿠키를 정상 송수신하도록 구성 |
| 자동로그인 | `__Host-HV-AUTOLOGIN`, 자동로그인 선택 시 90일 영속 | iOS·Android 모두 영속 쿠키 저장소를 사용하고, 앱 재실행 뒤에도 쿠키를 유지 |
| 앱 인증 관리 | JWT·네이티브 토큰 관리·브릿지 없음 | 토큰·키·쿠키를 네이티브 저장소에 별도 복사하거나 브릿지로 노출하지 않음 |
| 로그아웃 | 웹이 `/logout` POST와 CSRF 처리 수행 | 별도 네이티브 HTTP 호출 없이 WebView 내부 웹 동작을 그대로 사용 |

- 앱 시작·종료 시 WebView의 쿠키나 웹 데이터를 임의로 삭제하지 않습니다.
- 로그인 만료·인증 실패는 웹이 로그인 화면으로 이동시키므로, 앱의 별도 인증 실패 화면이나 토큰 갱신은 필요 없습니다.

### 4-2. VOC 사진 첨부

웹의 사진 첨부 입력을 Android·iOS에서 정상 사용할 수 있게 연결 부탁드립니다.

```html
<input type="file" accept="image/*" multiple>
```

- Android: WebView 파일 선택 요청을 OS 파일 선택기와 연결합니다.
- iOS: WebView 파일 선택 요청을 사진 보관함 및 카메라 선택 흐름과 연결합니다.
- 웹 입력의 `multiple` 속성을 반영해 여러 사진을 한 번에 선택한 경우 선택된 모든 파일을 웹에 전달합니다.
- OS 선택기 특성상 한 장씩 선택하는 흐름도 허용합니다. 웹은 추가 선택한 사진을 누적해 최대 3장까지 관리합니다.
- 카메라 또는 사진 보관함 접근이 필요한 시점에만 OS 권한을 요청합니다.
- 권한을 거부해도 사진 없이 VOC를 계속 작성·등록할 수 있어야 합니다.
- 파일 형식·용량·개수는 웹·서버 정책이 검증하므로 앱에서 별도 제한을 만들지 않습니다.

### 4-3. 기기 동작

**Android 뒤로가기**

- WebView에 이전 이력이 있으면 이전 웹 화면으로 이동합니다.
- 최초 진입 화면에서는 앱 종료 확인을 표시합니다.
- 웹 화면의 자체 뒤로가기 동작을 앱에서 중복 구현하지 않습니다.

**키보드**

- 로그인, 회원가입, 비밀번호 변경, VOC 작성 시 키보드가 입력창·버튼을 가리지 않게 처리합니다.
- Android는 키보드 표시 시 WebView 가용 영역이 리사이즈되도록 구성합니다.
- iOS는 키보드 표시·해제 후 안전 영역과 스크롤 위치가 비정상적으로 남지 않아야 합니다.
- 웹의 `viewport-fit=cover` 및 안전 영역 CSS를 앱이 방해하지 않습니다.

### 4-4. 로딩 실패·오프라인 지원 요청

최초 운영 URL 로딩 실패나 기기 오프라인 상황에서 빈 WebView가 보이지 않도록 지원 부탁드립니다.

- 간단한 오류 안내와 재시도 수단을 제공합니다.
- 재시도 시 동일 운영 URL을 다시 로드합니다.
- 웹 로드 이후의 로그인 만료·업무 오류는 기존 웹 서비스가 처리합니다.

## 5. 참고

- 웹에는 약 1.5초 뒤 로그인 화면으로 이동하는 스플래시가 있습니다. 앱 런치스크린은 시스템 기본 수준으로 짧게 적용해 이중 노출을 피합니다.
- 실제 운영 URL과 앱 배포·등록 방식은 별도 공유·협의합니다.
